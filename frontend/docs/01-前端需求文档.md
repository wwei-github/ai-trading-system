## 1. 文档说明

### 1.1 编写目的

本文档定义 AI 智能交易管理系统前端应用的完整需求规格，作为前端开发、设计、测试与验收的统一依据。文档明确以下内容：

- 明确 9 大功能模块的前端功能边界、页面布局与交互细节；
- 规范路由结构、状态管理、API 调用与类型定义；
- 约定组件层级、样式主题与非功能性指标；
- 为后续接口对接、联调与迭代提供基线参考。

### 1.2 适用范围

| 维度 | 说明 |
| --- | --- |
| 产品形态 | 加密货币交易管理 SaaS 系统（Web 端单页应用） |
| 端类型 | 桌面浏览器 Web 应用（暂不覆盖移动端原生 App） |
| 用户角色 | 个人交易者 / 系统管理员（当前版本无登录鉴权流程） |
| 文档读者 | 前端开发工程师、后端开发工程师、产品经理、测试工程师 |

### 1.3 术语与缩写

| 术语 | 说明 |
| --- | --- |
| SaaS | Software as a Service，软件即服务 |
| SPA | Single Page Application，单页应用 |
| PRD | Product Requirements Document，产品需求文档 |
| K 线 | 蜡烛图（Candlestick Chart），反映价格走势的图表 |
| RAG | Retrieval-Augmented Generation，检索增强生成 |
| 回测 | Backtest，基于历史数据验证策略表现 |
| 模拟交易 | Paper Trading，使用虚拟资金运行策略 |
| 实盘交易 | Live Trading，使用真实资金运行策略 |
| 技术指标 | Technical Indicator，如 MA、MACD、RSI、KDJ 等 |
| API | Application Programming Interface，应用程序接口 |
| CRUD | Create / Read / Update / Delete，增删改查 |

### 2.3 选型理由

| 技术 | 选型理由 |
| --- | --- |
| React 18 + TypeScript | 生态成熟、并发特性稳定；TS 在交易类强数据场景下提供编译期保障，降低运行时错误 |
| Vite 5 | 基于原生 ESM 的极速冷启动与 HMR，配置简洁；生产构建基于 Rollen，输出体积可控 |
| Ant Design 5 | 中后台场景组件齐全，CSS-in-JS 主题定制能力强，开箱即用的中文本地化 |
| React Router 6 | 数据路由 API（createBrowserRouter）与布局嵌套契合度高 |
| Zustand | API 极简、无样板代码、无 Provider 嵌套，适合中等复杂度的全局 UI 状态 |
| React Query | 自动缓存、失效重取、请求去重，天然适合列表/详情这类服务端状态；与 Zustand 职责互补 |
| ECharts + KLineCharts | ECharts 覆盖通用统计图表，KLineCharts 专为金融 K 线与叠加技术指标设计，两者互补 |

> **状态管理分工原则**：Zustand 负责「客户端 UI 状态」（如侧边栏折叠、主题切换）；React Query 负责「服务端数据状态」（如列表、详情、缓存失效）。两者职责不重叠。

## 3. 页面路由设计

### 3.1 路由总体设计

- 采用 `createBrowserRouter` 声明式路由配置，集中维护于 `src/router/index.tsx`。
- `MainLayout` 作为父路由的 `element`，通过 `<Outlet />` 渲染子页面，实现「左侧菜单 + 顶栏 + 内容区」统一布局。
- 菜单项配置统一维护于 `src/utils/constants.ts` 的 `menuItems`，路由与菜单共享同一 `key`（路由路径）。
- 路径别名 `@` 指向 `src` 目录（见 `vite.config.ts`）。
- 开发服务器端口 `5173`，`/api` 请求代理至 `http://localhost:18000`。

### 3.2 路由表

| 序号 | 路由路径 | 页面组件 | 菜单名称 | 菜单图标 | 是否需要登录 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | `/` | `Navigate → /dashboard` | - | - | 否 | 根路径重定向到工作台 |
| 1 | `/dashboard` | `pages/dashboard` | 工作台 | DashboardOutlined | 否 | 资产概览与快捷入口 |
| 2 | `/accounts` | `pages/accounts` | 交易所账号 | BankOutlined | 否 | 交易所账号管理 |
| 3 | `/trades` | `pages/trades` | 交易记录 | SwapOutlined | 否 | 交易记录增删改查 |
| 4 | `/statistics` | `pages/statistics` | 统计分析 | BarChartOutlined | 否 | 指标卡片与可视化图表 |
| 5 | `/coins` | `pages/coins` | 币种分析 | DotChartOutlined | 否 | 币种浏览与 K 线分析 |
| 6 | `/strategies` | `pages/strategies` | 交易系统 | ThunderboltOutlined | 否 | 策略库与回测/模拟/实盘 |
| 7 | `/books` | `pages/books` | 书籍学习 | BookOutlined | 否 | 书籍库与 RAG 问答 |
| 8 | `/ai` | `pages/ai` | AI 助手 | RobotOutlined | 否 | 对话与信号/报告生成 |
| 9 | `/system` | `pages/system` | 系统设置 | SettingOutlined | 否 | 用户/配置/通知/审计 |

> **说明**：当前版本暂未实现登录鉴权流程，所有路由均标记为「不需要登录」。`request.ts` 中已预留 Token 注入逻辑（注释状态），后续接入登录后通过路由守卫与请求拦截器统一启用。

### 3.3 路由守卫与登录策略

| 阶段 | 策略 |
| --- | --- |
| 当前版本 | 无登录流程，所有路由可直接访问；`request.ts` 请求拦截器中 Token 注入逻辑保持注释状态 |
| 预留扩展 | 后续接入登录时：1) 在 `router/index.tsx` 增加 `loader` 或高阶组件做鉴权重定向；2) 启用 `request.ts` 中 Token 注入；3) 401 响应统一跳转登录页 |
| 404 处理 | 暂未配置兜底 404 路由，建议后续补充 `path: '*'` 重定向到 `/dashboard` 或独立 404 页 |

## 4. 功能模块需求

### 4.1 工作台 (Dashboard)

#### 4.1.1 功能描述

工作台是用户登录后默认进入的首页，提供资产全局概览、当日交易简报与各功能模块的快捷入口，帮助用户快速掌握整体账户状况并跳转至对应功能区。

| 子功能 | 说明 |
| --- | --- |
| 资产概览 | 展示总资产、可用余额、冻结资金、今日盈亏、累计盈亏等核心资产指标 |
| 今日简报 | 展示今日交易笔数、成交金额、盈亏比例、活跃币种等当日数据摘要 |
| 快捷入口 | 提供到「录入交易」「新增账号」「新建策略」「AI 助手」等高频操作的快捷跳转卡片 |
| 资产趋势 | 展示近 7/30 日资产净值变化折线图 |

#### 4.1.2 页面布局描述

- 顶部：4 个核心资产指标卡片（`StatisticCard`），单行排列。
- 中部左侧：今日简报信息面板（`Card`），列出当日关键数据。
- 中部右侧：资产净值趋势折线图（`LineChart`）。
- 底部：快捷入口卡片网格（`Card` × N），点击跳转对应路由。

#### 4.1.3 交互需求

| 元素 | 交互 |
| --- | --- |
| 资产指标卡片 | 悬浮高亮；盈亏数据正负值用绿/红色区分 |
| 趋势图时间切换 | 提供「近 7 日 / 近 30 日」切换按钮，切换后重新请求数据 |
| 快捷入口卡片 | 点击跳转至对应路由（`/trades`、`/accounts`、`/strategies`、`/ai`） |
| 数据加载 | 使用 React Query 自动管理 loading / error 状态，配合 `Skeleton` 骨架屏 |

#### 4.1.4 API 调用列表

工作台无独立 API 模块，复用 `accounts` 与 `statistics` 模块：

| API 方法 | 所属模块 | 用途 |
| --- | --- | --- |
| `statisticsApi.getOverview()` | statistics.ts | 获取资产概览与今日简报 |
| `statisticsApi.getProfitTrend({ range })` | statistics.ts | 获取资产净值趋势 |
| `accountApi.getList()` | accounts.ts | 获取账号列表用于概览汇总 |

#### 4.1.5 状态管理需求

| 状态 | 存储位置 | 说明 |
| --- | --- | --- |
| 趋势时间范围 | 组件本地 state | 近 7 日 / 近 30 日切换 |
| 概览数据 | React Query 缓存 | `useQuery` 自动缓存，窗口聚焦不自动刷新 |

### 4.2 交易所账号管理 (Accounts)

#### 4.2.1 功能描述

支持多交易所（Binance、OKX、Bybit 等）账号的统一管理，包括账号的增删改查、API Key 连接测试与余额同步。

| 子功能 | 说明 |
| --- | --- |
| 账号列表 | 分页展示已绑定的交易所账号，含交易所、别名、状态、总资产、同步时间 |
| 新增账号 | 表单录入交易所类型、API Key、Secret、别名、备注 |
| 编辑账号 | 修改账号信息（Secret 仅可重置不可回显） |
| 删除账号 | 二次确认后软删除账号 |
| 连接测试 | 校验 API Key 是否有效并具备所需权限 |
| 余额同步 | 触发后端拉取最新余额并刷新资产 |

#### 4.2.2 页面布局描述

- 顶部工具栏：「新增账号」按钮、交易所筛选下拉、关键字搜索框、刷新按钮。
- 主体：`Table` 表格展示账号列表，列包含交易所、别名、状态（Tag）、总资产、可用余额、最后同步时间、操作列。
- 弹窗：新增/编辑使用 `Modal + Form`；连接测试结果用 `Modal` 或 `message` 提示。

#### 4.2.3 交互需求

| 元素 | 交互 |
| --- | --- |
| 新增按钮 | 打开新增弹窗，提交后刷新列表 |
| 编辑 | 打开编辑弹窗，Secret 字段默认置空（占位提示「留空表示不修改」） |
| 删除 | `Modal.confirm` 二次确认，删除成功后 `message.success` 并刷新 |
| 连接测试 | 操作列按钮，调用测试接口；进行中显示 `loading`，结果用成功/失败 `Tag` 或 `message` 反馈 |
| 余额同步 | 操作列按钮，同步中禁用并显示 `loading`，完成后刷新该行资产数据 |
| 状态标签 | 正常（绿色）/ 异常（红色）/ 同步中（蓝色）`Tag` |

#### 4.2.4 API 调用列表

| API 方法 | 所属模块 | HTTP | 用途 |
| --- | --- | --- | --- |
| `accountApi.getList(params)` | accounts.ts | GET | 获取账号分页列表 |
| `accountApi.getDetail(id)` | accounts.ts | GET | 获取账号详情 |
| `accountApi.create(data)` | accounts.ts | POST | 新增账号 |
| `accountApi.update(id, data)` | accounts.ts | PUT | 更新账号 |
| `accountApi.delete(id)` | accounts.ts | DELETE | 删除账号 |
| `accountApi.testConnection(id)` | accounts.ts | POST | 测试 API Key 连接 |
| `accountApi.syncBalance(id)` | accounts.ts | POST | 同步账号余额 |

#### 4.2.5 状态管理需求

| 状态 | 存储位置 | 说明 |
| --- | --- | --- |
| 列表筛选条件 | 组件本地 state | 交易所、关键字、分页 |
| 弹窗开关与表单 | 组件本地 state | `Modal` open、`Form` 实例 |
| 列表数据 | React Query 缓存 | 增删改后通过 `queryClient.invalidateQueries` 失效重取 |

### 4.3 交易记录 (Trades)

#### 4.3.1 功能描述

提供交易记录的全生命周期管理，支持手动录入、多条件筛选搜索、批量导入导出与标签化管理。

| 子功能 | 说明 |
| --- | --- |
| 记录列表 | 分页展示交易记录，含时间、币种、方向、数量、价格、金额、手续费、盈亏、标签 |
| 手动录入 | 表单录入单笔交易（交易所、币种、方向、数量、价格、时间、手续费、备注、标签） |
| 编辑/删除 | 修改或删除单条记录 |
| 筛选搜索 | 按交易所、币种、方向、时间范围、标签、关键字筛选 |
| 批量导入 | 上传 CSV/Excel 文件批量导入交易记录 |
| 批量导出 | 按当前筛选条件导出记录为文件 |
| 标签管理 | 标签的创建、绑定、解绑、删除 |

#### 4.3.2 页面布局描述

- 顶部：筛选区（`Form` 内联布局，含交易所、币种、方向、时间范围、标签、关键字输入与查询/重置按钮）。
- 工具栏：「新增交易」「批量导入」「批量导出」按钮。
- 主体：`Table` 表格，支持排序、分页；行操作列含编辑、删除；标签列以 `Tag` 形式展示。
- 弹窗：新增/编辑使用 `Modal + Form`；导入使用 `Upload` 组件弹窗。

#### 4.3.3 交互需求

| 元素 | 交互 |
| --- | --- |
| 筛选查询 | 点击查询触发列表刷新，重置清空筛选条件 |
| 新增交易 | 弹窗表单提交，方向为卖出时支持自动计算盈亏 |
| 编辑/删除 | 编辑回填表单；删除二次确认 |
| 批量导入 | `Upload` 限制文件类型与大小，上传后展示导入结果（成功/失败条数） |
| 批量导出 | 调用导出接口下载文件，导出中按钮 `loading` |
| 标签管理 | 录入表单内可新建标签；列表标签 `Tag` 可点击按标签筛选 |
| 盈亏列 | 正数绿色、负数红色，支持千分位与精度格式化 |

#### 4.3.4 API 调用列表

| API 方法 | 所属模块 | HTTP | 用途 |
| --- | --- | --- | --- |
| `tradeApi.getList(params)` | trades.ts | GET | 获取交易记录分页列表 |
| `tradeApi.getDetail(id)` | trades.ts | GET | 获取交易详情 |
| `tradeApi.create(data)` | trades.ts | POST | 手动录入交易 |
| `tradeApi.update(id, data)` | trades.ts | PUT | 更新交易 |
| `tradeApi.delete(id)` | trades.ts | DELETE | 删除交易 |
| `tradeApi.batchImport(file)` | trades.ts | POST | 批量导入（multipart） |
| `tradeApi.export(params)` | trades.ts | GET | 按条件导出文件 |
| `tradeApi.getTags()` | trades.ts | GET | 获取标签列表 |
| `tradeApi.createTag(data)` | trades.ts | POST | 创建标签 |
| `tradeApi.deleteTag(id)` | trades.ts | DELETE | 删除标签 |

#### 4.3.5 状态管理需求

## 7. API 调用规范

### 7.1 请求实例与拦截器

请求实例定义于 `src/api/request.ts`：

| 配置项 | 值 | 说明 |
| --- | --- | --- |
| `baseURL` | `import.meta.env.VITE_API_BASE_URL \|\| '/api/v1'` | 默认 `/api/v1`，可通过环境变量覆盖 |
| `timeout` | `15000` | 请求超时 15 秒 |

**请求拦截器**：

- 预留 Token 注入逻辑（当前注释状态，待登录流程启用）；
- 通过 `Authorization: Bearer <token>` 头部注入。

**响应拦截器**：

- 解析 `response.data` 为 `ApiResponse`；
- `code !== 0` 视为业务错误，调用 `message.error` 提示并 `reject`；
- 网络错误统一 `message.error(error.message)` 提示并 `reject`；
- 成功时返回 `res`（已剥离外层 `response`，便于业务直接取 `data`）。

### 7.2 统一响应格式

所有接口遵循统一响应结构（定义于 `src/types/api.ts`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | `number` | 业务状态码，`0` 表示成功，非 `0` 表示业务错误 |
| `message` | `string` | 提示信息 |
| `data` | `T` | 业务数据 |

分页响应结构：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `total` | `number` | 总条数 |
| `page` | `number` | 当前页码 |
| `page_size` | `number` | 每页条数 |
| `items` | `T[]` | 当前页数据列表 |

分页查询参数：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `page` | `number?` | 页码，默认 1 |
| `page_size` | `number?` | 每页条数，默认 20 |

### 7.3 错误处理策略

| 错误类型 | 处理方式 |
| --- | --- |
| 业务错误（`code !== 0`） | 响应拦截器统一 `message.error` 提示，业务侧可 catch 做额外处理 |
| 网络错误/超时 | 拦截器统一 `message.error('网络异常...')` 提示 |
| 表单校验错误 | 前端 `Form` 校验拦截，不发请求 |
| 401 未授权（预留） | 清除 Token，跳转登录页 |
| 文件上传错误 | `Upload` 组件 `beforeUpload` 校验 + 服务端返回错误提示 |

### 7.4 React Query 使用规范

`QueryClient` 在 `App.tsx` 中创建并注入，默认配置：

| 配置项 | 值 | 说明 |
| --- | --- | --- |
| `refetchOnWindowFocus` | `false` | 窗口聚焦不自动刷新 |
| `retry` | `1` | 失败重试 1 次 |

**使用约定**：

- 列表查询使用 `useQuery`，key 采用 `[module, 'list', params]` 结构；
- 增删改使用 `useMutation`，成功后 `queryClient.invalidateQueries({ queryKey: [module] })` 失效重取；
- 长任务（解析、回测、生成）可结合 `refetchInterval` 轮询状态；
- 全局配置中文 `locale`（`ConfigProvider locale={zhCN}`）。

## 8. 类型定义

### 8.1 通用类型

通用类型集中维护于 `src/types/api.ts`，已定义：

| 类型 | 定义 | 说明 |
| --- | --- | --- |

| `PaginatedResponse<T>` | `{ total: number; page: number; page_size: number; items: T[] }` | 分页响应 |

### 8.2 类型组织规范

| 规范 | 说明 |
| --- | --- |
| 通用类型 | 置于 `src/types/api.ts` |
| 各模块业务实体类型 | 建议按模块拆分 `src/types/{accounts,trades,...}.ts`，并在 `types/index.ts` 聚合导出 |
| API 方法入参/出参 | 每个 API 方法定义 ` XxxParams`、`XxxResult` 类型，与后端契约一致 |

| 路径别名 | 统一使用 `@/types/...` 引用 |

> **字段命名约定建议**：后端响应若为 `snake_case`（如 `page_size`、`created_at`），前端类型与之保持一致，避免在拦截层做全量转换引入隐性开销；组件内部展示按需格式化。

| 指标 | 目标 | 实现手段 |
