## 1. 开发总览与交付节奏

### 1.1 PRD 对齐：与 PRD §11 里程碑映射

| PRD 里程碑 | 周期 | 本方案阶段 | 说明 |
|------------|------|-----------|------|
| M1 基础框架 | 第 1-3 周 | Stage 0 + Stage 1 | 已完成（脚手架/布局/Docker） |
| M2 账号与交易 | 第 4-7 周 | Stage 2 + Stage 3 | 当前目标：账号全 CRUD + 连接测试 + 交易 CRUD + 导入导出 |
| M3 统计与币种 | 第 8-10 周 | Stage 4 + Stage 5 | 统计 12 指标 + 9 图表 + 币种列表 K 线 |

| V1.2 学习版 | M5-M6 | Stage 7 | 书籍上传 + RAG + 知识提取 |
| V1.3 AI 增强 | M7-M8 | Stage 8 | AI 全能力 + 信号 + 报告 |

### 1.2 各阶段交付定义（DoD）

每个阶段完成后均需：
- 所有页面能在 **local / docker / online** 三种模式下正常运行
- TypeScript 严格模式无错误（`tsc -b --noEmit` 通过）
- 关键流程通过组件单测（覆盖率 ≥ 60%）
- 与后端对应 API 联调通过（或 Mock 数据完备）
- 文档：变更同步更新至对应需求文档

```
Stage 1 (基础夯实)
    ↓
Stage 2 (账号管理) ─┐
                     ├──→ Stage 4 (统计分析) 依赖交易与账号数据
Stage 3 (交易记录) ──┘      ↑
                            │

                            │
Stage 6 (策略)  ────────────┤ 策略盈亏写入交易后统计
     ↑ 提取                 │

     ↑ RAG                  │
```

**开发顺序建议**：Stage 1 → (Stage 2 + Stage 3 并行，依赖共通组件) → Stage 4 → Stage 5 → (Stage 6/7/8 按优先级安排)

## 5. 关键技术点解决方案

| 技术点 | 方案 | 原因 |
|--------|------|------|
| **图表** | ECharts 5（@ant-design/charts 封装更易搭配 AntD） | 支持热力图/饼图/折线柱图散点全覆盖，与 AntD 主题匹配 |
| **K 线** | lightweight-charts（TradingView 开源） | 高性能、体积小、类型定义完善；K线/指标 pane 机制天然支持 |
| **PDF 阅读器** | pdfjs-dist（v3.x，umd 构建不走 native 模块） | 行业标准；可直接 import 不影响 Vite 构建 |
| **Excel 导入导出** | ExcelJS（支持流式读大文件 + xlsx 样式丰富） + PapaParse（CSV） | 相比 sheet.js 免费版导出样式更灵活 |
| **PDF 报表导出** | html2canvas + jsPDF（导出渲染后的 HTML 页面，排版一致性高） | 纯前端导出无需后端；可复用统计页面组件 |
| **流式对话** | `fetch` + `ReadableStream` + `TextDecoder`（SSE 标准），配合 react-markdown 渲染（流式增量渲染） | axios 对 SSE 支持弱，原生 fetch 更稳定；复用 axios 鉴权逻辑（手动加 header） |
| **WebSocket 行情** | React Hook + 重连机制（指数退避）+ Zustand store 分发；多页面订阅同一连接 | 避免多 Tab 建立多连接 |
| **Markdown 渲染** | react-markdown + remark-gfm + @uiw/react-md-editor（编辑态） | 免费、可定制；备注字段可编辑/预览切换 |
| **标签多选** | antd Select mode=multiple + 自定义 Tag 颜色输入 | 可新增标签 inline |
| **三种模式适配** | 保持 VITE_API_BASE_URL 与 request.ts resolveBaseURL 现有逻辑不变；新增 `ws` 连接同样基于模式推导 | 已骨架完成无需改动 |

## 7. 前后端对接计划与 Mock 策略

| 阶段 | 方式 | 说明 |
|------|------|------|
| **Stage 1-3（开发期）** | **前端先用 MSW Mock** | msw（Mock Service Worker）拦截 /api/v1/*，返回本地 JSON，并行开发 |
| **Stage 4+（联调期）** | **Docker 模式** | `npm run dev:docker` 调用容器后端，真实 PG/Redis |
| **验收期** | **online 模式** | 调用测试环境真实后端 |

### Mock 数据生成
- 每个 API 文件 `*_mock.ts` 存放 mock data（生成 30~100 条示例，基于 @faker-js/faker 或手写）
- MSW handlers：`mock/handlers.ts` 统一注册
- 仅 `VITE_USE_MOCK=true`（可通过 `.env.local`）开启，生产构建不包含

### 对接 Checklist
- [ ] 每个 API 方法签名与后端 OpenAPI `/openapi.json` 生成的 TypeScript 类型对比（可用 openapi-typescript-codegen 自动生成，V1 阶段可选）
- [ ] 统一分页格式：`{ total, page, page_size, items }`（PaginatedResponse）
- [ ] 统一响应：`{ code:0, message:"ok", data:T }`（ApiResponse）
- [ ] 错误码：4xx/5xx 映射为 message + code
- [ ] WebSocket 消息协议：`{ type:"quote"|"signal"|"progress", payload:T }`

## 9. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| lightweight-charts 自定义指标（KDJ/DMI 等）计算复杂 | 中 | 高 | 参考 trading-vue-js/ta.js 开源实现，或接入 `technicalindicators` 库；每种指标独立 UT 验证 |
| MSW 模拟数据与真实后端不一致 | 高 | 中 | Stage 2 结束前用 Docker 模式回归一次，修正类型差异 |
| RAG 向量库选型未定（pgvector vs Milvus） | 低 | 中 | Stage 7 前决定；V1.2 前可用后端内存模拟向量检索（小数据量） |
| 回测性能瓶颈：1 年 1h 级 8760 根 K 线 × 多策略并发 | 中 | 高 | 后端 Celery + numpy 向量化；前端显示进度 SSE；必要时 WebWorker 本地预回测 |
| 实盘风控复杂（V1 首版） | 中 | 极高 | 严格按 PRD §9 风控阈值实现；V1 默认"半自动人工确认下单"；提币功能默认禁用 |
| 多交易所行情数据差异（Binance vs OKX 价格/精度） | 中 | 中 | 行情聚合时统一精度；支持用户选择优先交易所账号 |
