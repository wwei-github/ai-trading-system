## 1. 架构概述

### 1.1 架构风格

本项目采用 **前后端分离 + Monorepo** 的架构风格：

- **前端**：React 18 + TypeScript + Vite 单页应用（SPA）
- **后端**：FastAPI（Python 3.11+） RESTful API 服务
- **异步层**：Celery Worker 处理耗时任务
- **数据层**：PostgreSQL（主库）+ Redis（缓存/队列）+ pgvector（向量检索）
- **AI 层**：LLM 适配器 + RAG 检索 + Agent 编排

### 1.2 核心设计原则

| 原则 | 说明 |
|------|------|
| **关注点分离** | 前端按页面/功能划分子目录；后端按业务模块划分 Service 层 |
| **依赖倒置** | 后端依赖抽象接口，CCXT/LLM 通过适配器注入 |
| **可测试性** | 业务逻辑独立于框架，Service 层可独立单元测试 |
| **渐进式增强** | V1 实现核心功能，预留扩展点（插件化交易所、AI 模型切换） |
| **安全优先** | 敏感数据加密存储，所有关键操作审计日志 |

## 3. 前端架构设计

### 3.1 技术选型决策

| 技术 | 版本 | 选择理由 |
|------|------|----------|
| **React** | 18.x | 生态成熟、社区活跃、团队熟悉 |
| **TypeScript** | 5.x | 类型安全，减少运行时错误，提升协作效率 |
| **Vite** | 5.x | 极速冷启动，HMR 迅速，开发体验好 |
| **Ant Design** | 5.x | 企业级组件库，覆盖表单、表格、图表等场景 |
| **Zustand** | 4.x | 轻量级状态管理，API 简洁，TypeScript 友好 |
| **React Query** | 5.x | 服务端数据管理，自动缓存与失效，减少样板代码 |
| **React Router** | 6.x | 主流路由方案，支持嵌套路由和数据加载 |
| **ECharts** | 5.x | 功能强大的图表库，支持丰富的统计图表 |
| **klinecharts** | 9.x | 专业 K 线图表库，支持技术指标叠加 |

## 6. 前后端契约规范

### 6.1 API 响应标准格式

```typescript
// 统一响应结构
interface ApiResponse<T> {
  code: number;      // 0 成功, 非 0 失败
  message: string;   // 描述信息
  data: T;           // 业务数据
}

// 分页响应
interface PaginatedResponse<T> {
  total: number;
  page: number;
  page_size: number;
  items: T[];
}

// 列表响应 (不分页)
interface ListResponse<T> {
  items: T[];
}
```

### 6.2 后端对应实现

```python
# schemas/common.py

from pydantic import BaseModel
from typing import Optional, TypeVar, Generic, List

T = TypeVar("T")

class ApiResponse(BaseModel, Generic[T]):
    code: int = 0
    message: str = "ok"
    data: Optional[T] = None

class PaginatedResponse(BaseModel, Generic[T]):
    total: int
    page: int
    page_size: int
    items: List[T]

class ListResponse(BaseModel, Generic[T]):
    items: List[T]

# 通用请求参数
class PaginationParams(BaseModel):
    page: int = 1
    page_size: int = 20

class TimeRangeParams(BaseModel):
    start_date: str  # YYYY-MM-DD
    end_date: str    # YYYY-MM-DD
```

### 11.1 Docker Compose 服务编排

```yaml
# docker-compose.yml

version: "3.9"

services:
  # 前端应用
  frontend:
    build:
      context: ./frontend
      dockerfile: ../docker/Dockerfile.frontend

      - VITE_API_BASE_URL=/api/v1
      - VITE_WS_URL=/ws
    depends_on:
      - backend

  # 后端 API
  backend:
    build:
      context: ./backend
      dockerfile: ../docker/Dockerfile.backend
    ports:
      - "8000:8000"
    environment:
      - APP_ENV=production
      - DATABASE_URL=postgresql+asyncpg://${DB_USER}:${DB_PASSWORD}@postgres:5432/trading
      - REDIS_URL=redis://redis:6379/0
      - SECRET_KEY=${SECRET_KEY}
      - AI_PROVIDER=${AI_PROVIDER}
      - AI_API_KEY=${AI_API_KEY}
    depends_on:
      - postgres
      - redis

  # Celery Worker
  celery-worker:
    build:
      context: ./backend
      dockerfile: ../docker/Dockerfile.celery
    command: celery -A app.celery_app worker --loglevel=info --concurrency=4
    environment:
      - APP_ENV=production
      - DATABASE_URL=postgresql+asyncpg://${DB_USER}:${DB_PASSWORD}@postgres:5432/trading
      - REDIS_URL=redis://redis:6379/0
      - SECRET_KEY=${SECRET_KEY}
    depends_on:
      - postgres
      - redis

  # Celery Beat (定时任务)
  celery-beat:
    build:
      context: ./backend
      dockerfile: ../docker/Dockerfile.celery
    command: celery -A app.celery_app beat --loglevel=info
    environment:
      - APP_ENV=production
      - DATABASE_URL=postgresql+asyncpg://${DB_USER}:${DB_PASSWORD}@postgres:5432/trading
      - REDIS_URL=redis://redis:6379/0
    depends_on:
      - postgres
      - redis

  # PostgreSQL
  postgres:
    image: postgres:15
    environment:
      - POSTGRES_DB=trading

      - pgdata:/var/lib/postgresql/data

      - redisdata:/data

      - "6379:6379"

      - "80:80"

      - ./docker/nginx.conf:/etc/nginx/nginx.conf
      - ./ssl:/etc/nginx/ssl
    depends_on:
      - frontend
      - backend

volumes:
  pgdata:
  redisdata:
```

### 11.2 Nginx 配置要点

```nginx
# docker/nginx.conf

server {
    listen 80;
    server_name trading.example.com;
    
    # 强制 HTTPS
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl;
    server_name trading.example.com;
    
    # SSL 配置
    ssl_certificate /etc/nginx/ssl/cert.pem;
    ssl_certificate_key /etc/nginx/ssl/key.pem;
    
    # 前端静态资源
    location / {
        proxy_pass http://frontend:80;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
    
    # 后端 API
    location /api/ {
        proxy_pass http://backend:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        
        # 请求体大小限制 (书籍上传)
        client_max_body_size 120M;
    }
    
    # WebSocket
    location /ws/ {
        proxy_pass http://backend:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }
}
```
