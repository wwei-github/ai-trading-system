## 1. 文档说明

### 1.1 文档目的

本文档定义 AI 智能交易管理系统后端的完整需求规范，作为后端开发、测试、验收的统一依据。文档覆盖以下内容：

- 明确系统技术栈与架构分层；
- 规范 API 设计约定、统一响应格式与错误码体系；
- 详列各业务模块的接口清单、请求/响应结构；
- 定义 13 个数据库模型的字段与关系；
- 描述 7 个业务服务的职责与核心方法；
- 规划 Celery 异步任务、CCXT 交易所接入、安全与配置策略；
- 约束性能、可测试性、日志等非功能需求。

### 1.2 文档范围

本系统为 AI 驱动的加密货币交易管理 SaaS 平台，后端需覆盖 PRD 定义的 9 大功能模块：

| 模块编号 | 模块名称 | 后端职责 |
| :---: | :--- | :--- |
| 1 | 交易所账号管理 | 账号 CRUD、连接测试、余额查询、订单同步 |
| 2 | 交易记录 | 交易 CRUD、批量导入导出、筛选搜索、标签管理 |
| 3 | 统计分析 | 核心指标计算、8 种图表数据接口、报表导出 |
| 4 | 币种分析 | 行情数据、K 线、技术指标计算、多币种对比 |
| 5 | 交易系统/策略 | 策略 CRUD、回测引擎、模拟交易、实盘交易 |
| 6 | 书籍学习 | 文件上传、内容解析、AI 知识提取、RAG 问答 |
| 7 | AI 助手 | 对话接口（5 种模式）、流式输出、信号生成、报告生成 |
| 8 | 系统设置 | 用户管理、系统配置、通知设置、审计日志 |
| 9 | 健康检查 | 系统健康状态 |

> **范围说明**：本项目当前不包含用户登录/认证流程（JWT/OAuth），用户模型主要用于数据关联与审计，预留认证扩展字段。

### 1.3 术语表

| 术语 | 说明 |
| :--- | :--- |
| SaaS | Software as a Service，软件即服务，多租户云端交付模式 |
| CCXT | 开源加密货币交易所统一接入库，支持 100+ 交易所 |
| RAG | Retrieval-Augmented Generation，检索增强生成，结合知识库的 AI 问答技术 |
| OHLCV | Open/High/Low/Close/Volume，K 线数据五要素 |
| PnL | Profit and Loss，盈亏 |
| 夏普比率 | 衡量风险调整后收益的指标 |
| 最大回撤 | 周期内资产从峰值回落的最大幅度 |
| Fernet | 基于 AES-128-CBC + HMAC-SHA256 的对称加密方案 |
| 异步 IO | 非阻塞 IO 模型，提升并发吞吐 |

### 2.2 选型理由

| 技术 | 选型理由 |
| :--- | :--- |
| **FastAPI** | 原生异步支持，适合高并发交易所数据拉取；基于 Pydantic 自动校验与 OpenAPI 文档生成，提升开发效率与接口可维护性。 |
| **SQLAlchemy 2.0** | 采用全新 `Mapped` 声明式语法，类型安全；异步引擎配合 asyncpg 实现非阻塞数据库访问；与 Alembic 无缝集成管理迁移。 |
| **PostgreSQL** | 原生支持 JSONB（存储策略规则、资产明细等半结构化数据）与 UUID 主键；事务一致性满足交易数据强一致需求。 |
| **Redis** | 双重角色：作为 Celery 消息代理承载异步任务，同时作为热点数据缓存（行情、统计结果），降低数据库压力。 |
| **Celery** | 交易所数据同步、策略回测、报告生成等耗时操作需异步执行，避免阻塞 API 线程；支持定时调度（beat）实现周期同步。 |
| **CCXT** | 一套统一接口对接 100+ 交易所，避免为每个交易所单独开发适配层；支持现货/合约、测试网、限流控制。 |
| **cryptography (Fernet)** | 交易所 API Key 属高敏感数据，必须加密存储；Fernet 提供带认证的对称加密，防止密文被篡改。 |
| **pandas + numpy** | 回测引擎需大量时间序列计算（收益率、回撤、夏普比率），pandas 提供高效向量化运算。 |
| **loguru** | 零配置即用，支持按天轮转、压缩归档、彩色输出、异常堆栈诊断，优于标准 logging 的开发体验。 |
| **Pydantic v2** | 性能较 v1 提升 5-50 倍；与 FastAPI 深度集成，请求自动校验、响应自动序列化。 |

## 3. API 设计规范

### 3.1 RESTful 规范

| 规范项 | 约定 |
| :--- | :--- |
| 路径前缀 | 所有接口统一前缀 `/api/v1`，便于版本演进 |
| 资源命名 | 使用复数名词（`/accounts`、`/trades`），小写中划线分隔 |
| HTTP 方法 | `GET` 查询、`POST` 创建、`PUT/PATCH` 更新、`DELETE` 删除 |
| 状态码 | 遵循 HTTP 标准语义（200/201/204/400/404/409/500/503） |
| 幂等性 | `GET`、`PUT`、`DELETE` 幂等；`POST` 非幂等 |
| 查询参数 | 分页、排序、过滤均通过 query 参数传递 |
| 路径参数 | 资源唯一标识使用 UUID 路径参数（`/accounts/{account_id}`） |
| 内容类型 | 请求/响应统一使用 `application/json`；文件上传使用 `multipart/form-data` |

### 3.2 统一响应格式

所有接口统一返回 `ApiResponse` 结构，定义于 `app/schemas/common.py`：

```json
{
  "code": 0,
  "message": "ok",
  "data": { ... }
}
```

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `code` | int | 业务状态码，`0` 表示成功，非 `0` 表示错误 |
| `message` | string | 响应消息，成功为 `"ok"`，失败为错误描述 |
| `data` | object/array/null | 响应数据，无数据时为 `null` |

> **设计说明**：HTTP 状态码与业务 `code` 双层语义。HTTP 状态码反映传输层状态，业务 `code` 反映业务逻辑状态，便于前端统一拦截处理。

### 3.3 错误码体系

错误码继承自 `AppException` 基类（`app/core/exceptions.py`），全局异常处理器统一捕获并转换为 `ApiResponse`。

| 异常类 | HTTP 状态码 | 业务 code | 默认消息 | 触发场景 |
| :--- | :---: | :---: | :--- | :--- |
| `BadRequestException` | 400 | 400 | 请求参数错误 | 参数校验失败、格式错误 |
| `NotFoundException` | 404 | 404 | 资源不存在 | 查询资源不存在 |
| `ConflictException` | 409 | 409 | 资源冲突 | 唯一约束冲突、状态冲突 |
| `ServiceUnavailableException` | 503 | 503 | 服务暂时不可用 | 数据库/交易所连接失败 |
| `AppException` | 500 | 500 | 服务内部错误 | 未捕获的业务异常 |
| 未捕获异常 | 500 | 500 | 服务内部错误 | 兜底处理，记录完整堆栈 |

**错误响应示例**：

```json
{
  "code": 404,
  "message": "资源不存在",
  "data": { "resource": "account", "id": "xxx" }
}
```

### 3.4 分页规范

分页响应统一使用 `PaginatedResponse` 结构，分页参数通过 `PaginationParams` 传递：

**请求参数**：

| 参数 | 类型 | 默认值 | 说明 |
| :--- | :---: | :---: | :--- |
| `page` | int | 1 | 页码，从 1 开始 |
| `page_size` | int | 20 | 每页条数，最大 100 |

**响应结构**：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "total": 150,
    "page": 1,
    "page_size": 20,
    "items": [ ... ]
  }
}
```

| 字段 | 类型 | 说明 |

## 8. 交易所接入层

### 8.1 CCXT 封装设计

交易所接入层封装于 `app/exchange/ccxt_client.py`，`CCXTClient` 类提供统一的交易所访问接口。

**设计要点**：

- **延迟创建**：`_get_client()` 延迟实例化 ccxt 客户端，避免未使用时加载；
- **动态交易所**：通过 `getattr(ccxt, exchange_name)` 动态创建不同交易所实例；
- **测试网支持**：`set_sandbox_mode(True)` 切换测试网；
- **限流控制**：`enableRateLimit=True` 启用 CCXT 内置限流；
- **统一异步接口**：所有方法为 `async`，适配 FastAPI 异步模型。

### 8.2 支持的交易所

通过 CCXT 支持 100+ 交易所，重点适配：

| 交易所 | exchange 标识 | 是否需要 passphrase | 说明 |
| :--- | :--- | :---: | :--- |
| Binance | `binance` | 否 | 全球最大现货/合约交易所 |
| OKX | `okx` | 是 | 需要 passphrase 口令 |
| Bybit | `bybit` | 否 | 衍生品为主 |
| 其他 | CCXT 支持的交易所 | 视情况 | 通过统一接口接入 |

### 8.3 统一接口

`CCXTClient` 提供以下统一方法：

| 方法 | 签名 | 说明 |

| `fetch_ohlcv` | `(symbol, timeframe, since, limit) → list` | 获取 K 线数据 |
| `fetch_ticker` | `(symbol) → dict` | 获取行情数据 |
| `create_order` | `(symbol, order_type, side, amount, price) → dict` | 创建订单 |

**构造参数**：

| 参数 | 类型 | 必填 | 说明 |

## 9. 安全设计

### 9.1 API Key 加密存储

加密工具位于 `app/utils/crypto.py`，采用 Fernet 对称加密方案。

| 项 | 说明 |
| :--- | :--- |
| 加密算法 | Fernet（AES-128-CBC + HMAC-SHA256） |
| 密钥派生 | `ENCRYPTION_KEY` 配置项 → SHA-256 哈希 → base64 编码 |
| 加密函数 | `encrypt(plaintext) → ciphertext` |
| 解密函数 | `decrypt(ciphertext) → plaintext` |
| 加密字段 | `api_key_encrypted`、`api_secret_encrypted`、`passphrase_encrypted` |

**安全要求**：

- API Key/Secret 明文仅在创建请求与调用交易所时存在于内存；
- 数据库仅存储密文；
- `ENCRYPTION_KEY` 必须在生产环境配置为随机长字符串，不得提交至代码库；
- 解密函数仅在 `AccountService.get_decrypted_credentials` 内调用，用于实例化 CCXT 客户端。

### 9.2 数据隔离

| 隔离维度 | 实现方式 |
| :--- | :--- |
| 用户数据隔离 | 所有业务查询均以 `user_id` 作为过滤条件，确保用户只能访问自己的数据 |
| 账号隔离 | 交易记录、资产快照查询同时关联 `account_id`，避免跨账号数据泄露 |
| 响应脱敏 | 账号响应体 `ExchangeAccountResponse` 不返回任何加密凭证字段 |

### 9.3 风控规则

| 规则 | 说明 |
| :--- | :--- |
| 权限最小化 | 账号 `permissions` 字段记录交易所授予的权限范围，前端展示提醒 |
| 测试网优先 | 新增账号建议先在测试网验证，`is_testnet` 字段标识 |
| 实盘交易确认 | 实盘下单接口需二次确认，避免误操作 |
| 审计追踪 | 关键操作（创建/删除账号、下单、同步）写入 `AuditLog`，记录动作、资源、IP |
| 状态管理 | 账号状态 `active/disabled/expired`，异常账号自动停用 |

## 11. 非功能需求

### 11.1 性能需求

| 需求项 | 指标 | 实现策略 |
| :--- | :--- | :--- |
| 异步 IO | 全链路异步，无阻塞调用 | FastAPI + asyncpg + SQLAlchemy 2.0 异步引擎 |
| 数据库连接池 | 池大小 10，溢出 20，超时 30s | `create_async_engine` 配置 `pool_size/max_overflow/pool_timeout` |
| 连接健康检测 | 连接前 ping 检测，避免使用失效连接 | `pool_pre_ping=True` |
| 连接回收 | 每小时回收连接，防止长连接失效 | `pool_recycle=3600` |
| 延迟连接 | 数据库未启动不影响应用启动 | 异步引擎延迟连接，`lifespan` 不建立连接 |
| 缓存 | 热点数据（行情、统计）Redis 缓存 | Redis 作为缓存层 |
| 异步任务 | 耗时操作不阻塞 API | Celery 处理同步、回测、报告 |
| 限流 | 交易所 API 限流 | CCXT `enableRateLimit=True` |

**数据库会话管理**（`app/core/database.py`）：

- `get_db()` 作为 FastAPI 依赖注入，自动管理会话生命周期；
- 成功提交（commit）、异常回滚（rollback）、最终关闭（close）；
- `expire_on_commit=False` 避免提交后属性失效；
- `autoflush=False` 显式控制 flush 时机。

### 11.2 可测试性

| 需求项 | 实现策略 |
| :--- | :--- |
| 分层架构 | 路由 → 服务 → 模型三层分离，服务层可独立单元测试 |
| 依赖注入 | 数据库会话通过 `get_db` 依赖注入，测试时可替换为测试会话 |
| 配置隔离 | 配置通过 `Settings` 类管理，测试环境可覆盖环境变量 |
| 异常可控 | 自定义异常体系，测试可断言特定异常类型 |
| 无认证耦合 | 当前无认证流程，测试无需构造认证 token |
