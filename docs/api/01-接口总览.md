## 2. 认证与鉴权

### 2.1 JWT Bearer Token

需要登录的接口在请求头携带：

```http
Authorization: Bearer <access_token>
```

| Token 类型 | 默认有效期 | 说明 |
|---|---|---|
| access_token | 30 分钟 | 接口鉴权；`jwt[type]=access` |
| refresh_token | 7 天；勾选"记住我"为 30 天 | 用于刷新 access_token；`jwt[type]=refresh` |

登录 / 注册 / 刷新 / 密码重置 / 邮箱验证等鉴权接口本身不需要 Token。

### 2.2 RBAC 三角色

系统定义三种用户角色（`app/core/permissions.py` 的 `require_roles` / `reject_viewer_write`）：

| 角色 | 读（GET） | 写（POST/PATCH/PUT/DELETE） | 专属权限 |
|---|---|---|---|
| Admin | ✅ 全部 | ✅ 全部 | 用户管理（角色变更/重置密码）、审计日志、系统配置 |
| Trader | ✅ 自己数据 | ✅ 自己数据 | 所有业务写操作（账号/交易/策略/标签/导入导出） |
| Viewer | ✅ 自己数据 | ❌ 全部 | — |

> **实现方式**：业务路由统一挂 `dependencies=[Depends(reject_viewer_write)]`，写操作返回 403；Admin 专属接口使用 `@require_roles("admin")`。

### 2.3 2FA 二次校验

用户开启 TOTP 后，**高危动作**（密码修改、删除账号、提现/资金划转 — V1 已禁用提现）会额外校验 2FA。

## 3. 限流策略

中间件 `app/middleware/rate_limit_middleware.py` 基于内存 + `asyncio.Lock` 的令牌桶实现，默认策略：

| 类别 | 窗口 | 额度 | 识别键 |
|---|---|---|---|
| 登录接口 | 1 分钟 | 10 次 | IP |
| 交易写入 | 1 分钟 | 60 次 | user_id |
| AI 接口 | 1 分钟 | 20 次 | user_id |
| 上传接口 | 1 分钟 | 10 次 | user_id |
| 其他 | 1 分钟 | 300 次 | IP 或 user_id |

超出额度返回 `429 Too Many Requests`：

```json
{
  "code": 429,
  "message": "请求过于频繁，请稍后再试",
  "detail": {"category": "login", "retry_after_ms": 30000}
}
```

## 4. 统一响应格式

### 4.1 成功响应 `ApiResponse<T>`

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

- `code=0` 表示成功；非 0 见错误码表。
- `data` 为单个对象、数组或分页对象（见 4.2）。

### 4.2 分页响应 `PaginatedResponse<T>`

所有列表接口使用标准分页返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "total": 128,
    "page": 2,
    "page_size": 20,
    "items": [ { }, { } ]
  }
}
```

查询参数：`page`（默认 1，≥1），`page_size`（默认 20，范围 1~100）。

### 4.3 错误响应

```json
{
  "code": 40002,
  "message": "邮箱或密码错误",
  "detail": {"attempts": 3, "lock_minutes": 30}
}
```

- HTTP 状态码 与 `code` 字段 保持语义一致（`app/core/exceptions.py`）。
- `detail` 可选，提供机器可读的附加信息。

### 4.4 错误码速查

| HTTP 状态 | code | message 示例 | 触发场景 |
|---|---|---|---|
| 400 | 40000 | 请求参数错误 | 校验失败 / Pydantic ValidationError |
| 400 | 40001 | 邮箱已存在 | 注册邮箱冲突 |
| 400 | 40002 | 邮箱或密码错误 | 登录失败 |
| 400 | 40003 | 账号已被锁定 | 登录失败 ≥5 次 → 30 分钟锁定 |
| 400 | 40004 | 邮箱验证链接已过期 | verify-email token 过期 |
| 400 | 40005 | 交易所 API Key/Secret 无效 | 连接测试失败 |
| 400 | 40006 | 该账号有近 30 天的关联交易记录，无法删除 | 删除账号依赖检查 |
| 400 | 40007 | 交易所同步的交易记录仅允许更新标签/备注/策略关联 | 来源只读保护 |
| 401 | 40100 | 未认证或 Token 无效 | JWT 缺失 / 过期 / 类型错误 |
| 401 | 40101 | 2FA 校验失败 | 开启 TOTP 后缺少 `X-2FA-Token` 或错误 |
| 401 | 40102 | 邮箱未验证 | 未验证邮箱超出每日交易上限（10 条） |
| 403 | 40300 | 无权限执行该操作 | RBAC 角色不满足 |
| 403 | 40301 | Viewer 角色不允许写操作 | 业务写操作拒绝 |
| 403 | 40302 | 提币/资金划转功能在 V1 已禁用 | WithdrawDisabledError |
| 404 | 40400 | 资源不存在 | 账号 / 交易 / 策略 / 标签未找到 |
| 409 | 40900 | 资源冲突 | 标签名重复 / 更新 name 冲突 |
| 429 | 42900 | 请求过于频繁 | 限流中间件拒绝 |
| 500 | 50000 | 服务器内部错误 | 未捕获异常；500 错误触发告警邮件 |

## 5. 审计日志

所有写操作（除登录类接口外）经由 `app/middleware/audit_middleware.py` 自动写入 `audit_logs` 表，
或在路由中显式调用 `write_audit_log(db, ...)`。

审计动作类型（10 类）：`create / update / delete / import / export / login / logout / password_change / sync / system_config`。

敏感字段写入时自动脱敏（`mask_sensitive()`）：API Key / Secret / Passphrase / 密码哈希 / JWT。

审计日志查看：Admin 角色 `GET /users/audit-logs`（见 [13-users.md](./13-users.md)）。

## 6. 时区与时间格式

- 后端统一 UTC 存储，字段类型 `DateTime(timezone=True)`。
- API 传输均为 ISO-8601（带 Z 或偏移）：`2026-08-01T14:00:00+08:00` / `2026-08-01T06:00:00Z` 均可。
- Celery Beat 调度（`app/tasks/__init__.py`）使用 UTC 时区。

---

## 7. 小数与货币

- 所有金额/数量使用 `Decimal`（Pydantic `decimal.Decimal`，Postgres `NUMERIC(20,8)`），
  **禁止 JSON 浮点数直接计算**。
- 盈亏比值 `pnl_ratio` 精度 `NUMERIC(10,4)`。
- 盈亏引擎使用 `getcontext().prec = 28`（`app/services/pnl.py`）。
