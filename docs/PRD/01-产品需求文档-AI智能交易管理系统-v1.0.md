## 1. 文档说明

### 1.1 目的
本文档用于定义「AI 智能交易管理系统」的业务需求、功能规格、业务规则与交互逻辑，作为产品、设计、研发、测试各团队协同交付的统一依据。

### 1.2 范围
- **包含**：用户与权限、交易所账号管理、交易记录、统计分析、币种分析、书籍学习、交易系统（策略）管理、AI 助手、系统设置共 9 大核心模块的业务需求。
- **不包含**：底层数据库 DDL、后端接口详细技术规范、前端组件实现细节（见对应技术设计文档）。

### 1.3 术语与缩写

| 术语 | 释义 |
|------|------|
| 交易系统 | 一套包含入场、出场、仓位、风控规则的完整策略体系，可回测、模拟或实盘运行 |
| 策略 | 与"交易系统"同义，可互换使用 |
| Paper Trading / 模拟交易 | 接入真实行情但不涉及真实资金的模拟执行环境 |
| 实盘 / Live | 使用真实资金进行交易 |
| 回测 | 基于历史行情数据验证策略表现的过程 |
| RAG | 检索增强生成，结合知识库检索与大模型问答能力 |
| KYC | 实名认证（本系统暂不包含，但交易所侧需） |
| 2FA | 双因素认证（TOTP 等） |
| PnL | 盈亏（Profit and Loss） |
| 胜率 | 盈利交易数 / 已平仓总交易数 |
| 盈亏比 | 平均盈利 / 平均亏损 |
| 最大回撤 | 权益从峰值到谷值的最大跌幅 |
| 夏普比率 | 风险调整后收益指标 |

## 2. 产品概述

### 2.1 产品背景

加密货币市场 7×24 小时运行、波动剧烈、交易所众多。个人交易者普遍面临以下痛点：

1. **账号分散**：同时在多个交易所开户，资产与交易记录割裂，无法统一查看。
2. **复盘缺失**：交易仅以"记忆+表格"方式记录，无法量化评估交易表现与策略优劣。
3. **分析困难**：缺乏系统化的统计维度（胜率、盈亏比、回撤、币种贡献度等），难以发现问题。
4. **学习成本高**：交易书籍知识难以落地为可执行策略，学习内容与实盘脱节。
5. **策略执行难**：人工盯盘耗时耗力，情绪化操作频繁，纪律性执行困难。
6. **信息过载**：面对海量行情与资讯，缺乏 AI 辅助筛选与解读。

本产品旨在通过"管理 + 分析 + 学习 + AI"一体化方案，帮助交易者建立**可量化、可复盘、可学习、可执行**的交易闭环。

### 2.2 产品定位

面向**个人投资者、量化爱好者、小型交易团队**的**AI 驱动加密货币交易管理 SaaS**。核心是**管理与赋能**，而非单纯的自动化量化交易机器人（Bot）。系统强调：

- 交易记录与资产的**统一管理**
- 交易表现的**多维分析与复盘**
- 交易知识的**学习沉淀与系统化**
- 策略的**构建、回测、模拟、实盘**全流程
- AI 对**信息解读、信号发现、风险预警**的辅助

### 2.3 产品目标（目标周期：上线后 6 个月）

| 维度 | 目标 | 衡量口径 |
|------|------|----------|
| 用户规模 | 注册用户 ≥ 1,000，月活 ≥ 500 | 注册数、MAU |
| 活跃留存 | 次月留存 ≥ 40% | M2 / M1 |
| 核心功能渗透 | 80% 活跃用户使用交易记录；40% 使用策略回测；20% 实盘绑定 | 功能使用率 |
| 交易数据量 | 累计管理交易记录 ≥ 10 万条 | 业务数据量 |
| AI 使用 | 日均 AI 对话 ≥ 1,000 轮 | AI 功能调用量 |
| 满意度 | NPS ≥ 30 | NPS 调研 |

### 2.4 核心价值主张

| 目标用户 | 核心痛点 | 产品价值 |
|----------|----------|----------|
| 主观交易者 | 凭感觉交易，无法复盘改进 | 强制记录 → 量化指标 → 发现薄弱环节 |
| 策略研究者 | 策略验证与实盘割裂 | 统一回测 → 模拟 → 实盘的闭环 |
| 多交易所用户 | 资产与订单分散 | 多账号统一视图、一键分析 |
| 学习型交易者 | 书籍知识难落地 | AI 提取交易系统 → 直接转为可回测策略 |
| 信息焦虑者 | 资讯过载解读难 | AI 市场简报、风险预警、情绪分析 |

## 3. 用户角色与使用场景

### 3.1 用户角色定义

| 角色 | 说明 | 典型特征 | 核心诉求 |
|------|------|----------|----------|
| 管理员 Admin | 系统超级用户 | 平台运营者 | 用户管理、系统配置、审计 |
| 交易员 Trader | 有交易行为的普通用户 | 核心用户，实盘交易者 | 管理账号、记录交易、使用策略、AI 分析 |
| 观察者 Viewer | 无交易权限的只读用户 | 学员、合伙人、财务 | 查看报表、观察交易、不介入执行 |

> 权限矩阵详见功能模块内说明。

### 3.2 典型用户画像

#### 画像 1：主观交易者 · 张小明
- 身份：30 岁工程师，业余交易 1 年，主要做 BTC/ETH 现货与合约
- 行为：每天看盘 2-3 小时，手动下单，使用 2-3 个交易所
- 痛点：交易后没有系统记录，月度复盘发现"赚钱的都不知道为什么赚"
- 诉求：希望强制自己用系统记录每笔交易，并通过统计发现自己的"胜率时段"与"亏损币种"

#### 画像 2：策略研究者 · 李量化
- 身份：40 岁私募研究员，业余研究加密量化
- 行为：喜欢阅读交易书籍（《海龟交易法则》等），想把书中规则量化
- 痛点：写回测脚本太繁琐，且回测结果与最终实盘工具不一致
- 诉求：希望将书中规则通过可视化配置 + AI 提取快速变成策略，一键回测

#### 画像 3：小团队负责人 · 王老板
- 身份：管理 3 人交易团队，每人分工不同
- 行为：统一管理资金账号，需要定期汇总绩效并复盘
- 痛点：每人 Excel 格式不统一，合并报表耗时，策略不透明
- 诉求：统一平台管理多账号，多角色分权，实时查看团队绩效

### 3.3 典型使用场景

#### 场景 1：日常记账与复盘（交易员）
```
早上 9:00
  → 打开「工作台」查看隔夜资产变化与今日简报
  → 打开「交易记录」手动录入昨晚的 2 笔主观交易，关联标签"主观-BTC突破"
  → 切换到「统计分析」查看本周盈亏，发现 SOL 的交易胜率仅 20%
  → 与 AI 助手对话："为什么我最近 SOL 交易表现差？帮我分析原因"
  → AI 结合 SOL 交易时段、K 线与用户规则，输出原因与建议
```

#### 场景 2：从书籍中提取并验证策略（策略研究者）
```
周末下午
  → 打开「书籍学习」上传《海龟交易法则》PDF
  → 等待 AI 解析目录与内容，进入「知识提取」
  → AI 自动识别并生成一套"海龟突破"交易系统（唐奇安通道、ATR 止损、2N 加仓）
  → 打开「策略回测」，选择 BTC / 4h / 近 2 年 / 10000 USDT 初始资金
  → 10 分钟后得到回测结果：年化 38%、最大回撤 22%、胜率 42%、盈亏比 3.1
  → 启动模拟交易观察实时表现
```

#### 场景 3：团队管理与审计（管理员）
```
月末
  → 创建 2 个新团队成员账号，分别授予 Trader / Viewer 角色
  → 分配交易所账号权限：共享主账号只读权限
  → 查看「统计分析-团队视角」汇总月度报表
  → 导出 PDF 发给合伙人
  → 在「审计日志」检查是否有高风险操作（实盘启动、权限变更）
```

#### 场景 4：智能预警与辅助决策（交易员）
```
盘中
  → 系统检测到持仓 ETH 的波动率超过 ATR 2 倍
  → 推送风险预警："ETH 波动率异常，建议关注止损位下移"
  → 打开「币种分析-ETH」查看 AI 给出的支撑阻力
  → 与 AI 讨论："现在我持有 ETH 多单，浮盈 8%，该减仓还是持有？"
  → AI 给出 3 种方案与各自的风险收益评估，用户手动决策
```

## 4. 整体业务流程

### 4.1 用户生命周期流程

```
注册 → 登录 → 完善资料 → 绑定交易所账号
                                    ↓
                       ┌────────────┴────────────┐
                       │                         │
                  手动记录交易              自动同步订单
                       │                         │
                       └────────────┬────────────┘
                                    ↓
                             交易数据沉淀
                                    ↓
                  ┌─────────────────┼─────────────────┐
                  ↓                 ↓                 ↓
             统计分析复盘       币种分析研究       书籍学习沉淀
                  │                 │                 │
                  └─────────────────┼─────────────────┘
                                    ↓
                            构建/优化交易系统
                                    ↓
                  ┌─────────────────┼─────────────────┐
                  ↓                 ↓                 ↓
               历史回测          模拟交易          实盘执行
                  │                 │                 │
                  └─────────────────┼─────────────────┘
                                    ↓
                           绩效监控 → 迭代优化
```

### 4.2 实盘交易风控流程

```
用户启动实盘策略
      ↓
 风控校验（单笔上限 / 日累计 / 最大持仓 / 最大回撤阈值）
      ↓
  通过？─ 否 → 返回失败原因
      ↓ 是
 二次确认（登录密码 + 可选 2FA）
      ↓
 启动实时监听（行情 + 交易所推送）
      ↓
 策略触发信号 → 风控拦截（余额、权限、禁提币）
      ↓
 下单 → 记录 → 推送通知
      ↓
 持续监控：若当日达到最大回撤阈值 → 自动止停并告警
```

## 5. 功能需求详细说明

> 说明：每个模块按「功能描述 + 业务规则 + 输入输出 + 异常处理」结构描述。

---

### 5.1 用户与权限模块

#### 5.1.1 注册与登录

| 项目 | 内容 |
|------|------|
| 功能描述 | 提供账号注册、登录、登出、密码找回能力 |

**业务规则**
- R1：注册使用邮箱 + 密码；密码长度 8-32 位，至少包含字母与数字。
- R2：注册成功后发送验证邮件，未验证邮箱限制每日交易记录数 ≤ 10 条。
- R3：登录错误连续 5 次锁定账号 30 分钟；支持 IP 异常登录邮件告警。
- R4：登录采用 JWT Access Token（30 分钟）+ Refresh Token（7 天）。
- R5：支持"记住我"选项（延长 Refresh Token 至 30 天）。
- R6：登出需后端销毁 Refresh Token。
- R7：密码找回通过邮箱验证码重置，验证码有效期 15 分钟。

**输入输出**
| 动作 | 输入 | 输出 |
|------|------|------|
| 注册 | 邮箱、密码、确认密码、昵称 | 用户 ID、默认角色 Trader |
| 登录 | 邮箱、密码、是否记住我 | Access Token、Refresh Token、用户信息 |
| 登出 | Refresh Token | 成功标志 |
| 找回密码-发送 | 邮箱 | 验证码 |
| 找回密码-重置 | 邮箱、验证码、新密码 | 成功标志 |

**异常处理**
- 邮箱已注册 → 明确提示"该邮箱已注册"（避免撞库的话需模糊，但本产品非高敏可用明确提示）。
- 登录锁定 → 提示剩余锁定时间。
- 邮箱服务异常 → 提示稍后重试，后台重试队列。

#### 5.1.2 角色与权限

| 角色 | 权限概览 |
|------|----------|
| Admin | 用户管理、角色分配、系统配置、审计日志、全部功能 |
| Trader | 个人交易全功能（账号、交易、策略、AI、书籍）；无用户与系统管理权限 |
| Viewer | 只读查看报表、交易、资产；无创建、编辑、实盘、模拟、上传权限 |

**业务规则**
- R1：角色不可自助变更，由 Admin 调整。
- R2：一个用户仅属于一个角色。
- R3：实盘与模拟权限仅 Admin / Trader 角色可用。
- R4：所有涉及资金/权限的操作写入审计日志。

#### 5.1.3 个人中心

| 项目 | 内容 |
|------|------|
| 功能描述 | 修改个人资料、密码、头像；开启/关闭 2FA；管理登录设备 |

**业务规则**
- R1：修改密码需输入旧密码。
- R2：2FA 使用 TOTP（Google Authenticator 兼容），开启时校验一次验证码。
- R3：登录设备列表展示设备名、IP、最近登录时间；可强制下线指定设备。

### 5.2 交易所账号管理模块

#### 5.2.1 账号管理

| 项目 | 内容 |
|------|------|
| 功能描述 | 添加/编辑/删除交易所 API 账号；支持多交易所、多账号 |

**支持的交易所（V1 首版）**：Binance、OKX、Bybit、Huobi、Gate、Coinbase（后续可扩展）。

**业务规则**
- R1：一个用户可绑定多个交易所账号，每个账号有自定义标签（如"币安-现货主"）。
- R2：API Key / Secret 必须加密存储，禁止明文展示；前端仅显示首尾各 4 位。
- R3：每个账号需指定权限等级：
  - **只读**：仅查余额/订单；
  - **交易**：可下单（默认推荐）；
  - **提币**：默认关闭，需单独开关 + 二次确认，且 V1 首版可禁用提币权限（风控要求）。
- R4：支持"测试网/主网"切换，测试网账号带显著标识。
- R5：新增账号后必须执行"连接测试"，成功后才能使用。
- R6：支持账号启用/停用；停用后不进行任何数据同步与交易。
- R7：账号数量限制：普通用户 ≤ 10 个；可后续升级套餐。

**输入输出**
| 动作 | 输入 | 输出 |
|------|------|------|
| 新增账号 | 交易所、标签、API Key、Secret、Passphrase(可选)、权限、测试网 | 账号 ID、连接测试结果 |
| 编辑账号 | 同上（不含部分字段可不改） | 成功标志 |
| 删除账号 | 账号 ID | 成功标志（需二次确认） |
| 连接测试 | 账号 ID | 成功/失败原因 |

#### 5.2.2 余额与同步

| 项目 | 内容 |
|------|------|
| 功能描述 | 查询账号余额、资产快照、自动同步订单 |

**业务规则**
- R1：余额查询支持手动刷新与自动同步（默认每 10 分钟一次，可配置）。
- R2：每次余额同步生成一条资产快照，用于资产曲线。
- R3：历史订单自动同步默认每 30 分钟一次，支持手动触发。
- R4：订单同步以交易所订单 ID 为去重键，避免重复。
- R5：同步失败自动重试 3 次，超过后将账号置为"异常"状态并通知用户。

### 5.3 交易记录模块

#### 5.3.1 交易记录 CRUD

| 项目 | 内容 |

**交易字段口径**
| 字段 | 说明 | 必填 | 备注 |

| 交易对 | 如 BTC/USDT | 是 | |
| 方向 | 买入 / 卖出 | 是 | |
| 订单类型 | 市价 / 限价 / 条件单 | 是 | 默认市价 |
| 价格 | 下单/成交均价 | 是 | 市价单可填实际成交均价 |
| 数量 | 成交数量 | 是 | 以基础币为单位 |
| 杠杆倍数 | 1~125 | 合约必填 | 现货固定为 1 |
| 手续费 | 金额 | 否 | |
| 手续费币种 | 如 USDT / BNB | 否 | |
| 止盈价 | 可选 | 否 | |
| 止损价 | 可选 | 否 | |
| 成交状态 | 挂单 / 部分成交 / 已成交 / 已撤销 | 是 | 默认已成交 |
| 成交时间 | 时间戳 | 是 | |
| 关联策略 | 可关联某交易系统 | 否 | |
| 标签 | 多选标签 | 否 | 如"主观-突破"、"中线"等 |

**业务规则**
- R1：交易记录以"已平仓"为默认录入场景（也允许录入开仓未平仓）。
- R2：盈亏自动计算：
  - 现货：（卖出价 - 买入价）× 数量 - 手续费
  - 合约：根据开平仓配对计算；若仅录入开仓，则盈亏按未实现标记
- R3：支持按时间范围、交易对、账号、策略、标签、方向、盈亏状态等维度筛选。
- R4：支持全字段搜索（交易对、备注、标签）。
- R5：删除交易记录需二次确认。
- R6：自动同步的交易记录标记来源"交易所同步"，可编辑但不可删除关联关系。

### 5.6 交易系统（策略）管理模块

#### 5.6.1 策略库管理

| 项目 | 内容 |
|------|------|
| 功能描述 | 创建、编辑、克隆、删除、分类交易系统；支持模板库 |

**策略分类**
| 分类 | 说明 |
|------|------|
| 趋势追踪 | 突破、均线、通道等 |
| 震荡反转 | RSI 超买超卖、支撑阻力、网格类部分逻辑 |
| 套利策略 | 期现套利、跨所套利（需多账号） |
| 网格策略 | 区间网格、马丁策略 |
| 自定义 | 用户自由定义规则组合 |

**业务规则**
- R1：一个策略含 4 个核心组成：入场规则、出场规则、仓位管理、风控参数。
- R2：支持"克隆"快速创建变体。
- R3：内置 3 套模板策略（双均线、RSI 反转、海龟突破）作为示例。
- R4：来源书籍的策略标记来源关联。

#### 5.6.2 策略规则定义

**入场规则配置项**
- 技术条件：MA 交叉、RSI 阈值、MACD 金叉死叉、价格突破 X 日高低点、ATR 倍数突破等
- 逻辑组合：AND / OR / 嵌套（最多 3 层）
- 时间过滤：只在某时段 / 星期交易
- 多周期共振：需 4h + 1d 同方向确认

**出场规则配置项**
- 止盈：固定比例、ATR 倍数、MA 反向穿越
- 止损：固定比例、ATR 倍数、最近 N 日高低点
- 移动止损（Trailing Stop）
- 时间止损：持仓超过 N 周期

**仓位管理配置项**
- 固定手数 / 固定金额 / 固定比例（如每次用余额的 1%）
- 凯利公式 / 固定分数凯利
- 加仓规则：浮盈 X% 加 Y% 仓位，最多 N 次

**风控参数**
- 单笔最大亏损占总资金 %
- 每日最大亏损占总资金 %（达到则停止当日交易）
- 最大持仓数量（同币种 / 总体）
- 最大连续亏损次数（达到则暂停策略）

#### 5.6.3 历史回测

| 项目 | 内容 |
|------|------|
| 功能描述 | 基于历史 K 线运行策略，输出回测报告 |

**输入**
| 字段 | 说明 |
|------|------|
| 交易对 | 如 BTC/USDT |
| 时间周期 | 1m~1w，默认 1h / 4h |
| 回测区间 | 起止日期，默认近 1 年 |
| 初始资金 | USDT 金额，默认 10000 |
| 手续费率 | 默认 0.1%（买卖双向），可配置 |
| 滑点模拟 | 默认 0，可配置 0.05% 等 |
| 策略参数 | 使用当前参数或参数组合（网格搜索 V1.1） |

**输出（回测报告）**
1. **核心指标**：总收益率、年化、最大回撤、夏普、胜率、盈亏比、交易次数
2. **图表**：
   - 权益曲线（含基准对比）
   - 回撤曲线
   - 月度盈亏热力
   - 每笔交易盈亏散点
3. **明细表**：
   - 开平仓列表（时间、价格、数量、盈亏）
   - 每日持仓快照
4. **分析**：
   - AI 给出策略优缺点与可能的改进方向（可选）

**业务规则**
- R1：回测使用异步任务，可关闭页面后后台运行；完成后通知。
- R2：支持保存多次回测记录（同一策略不同参数/区间），可对比 2 次回测结果。
- R3：回测中交易数据不入库至用户交易记录。

#### 5.6.4 模拟交易（Paper Trading）

| 项目 | 内容 |
|------|------|
| 功能描述 | 使用真实行情驱动策略执行，记录虚拟盈亏，不涉及真实资金 |

**业务规则**
- R1：用户选择策略 + 账号（映射为虚拟账号）+ 初始虚拟资金启动。
- R2：模拟引擎订阅实时行情（WebSocket），按策略规则生成信号。
- R3：成交按"收盘/对手价+滑点"模拟。
- R4：模拟交易记录展示在独立的"模拟交易视图"，不与真实交易混合。
- R5：支持暂停/恢复/终止。

#### 5.6.5 实盘交易

| 项目 | 内容 |
|------|------|
| 功能描述 | 绑定交易所账号，策略直接下单 |

**业务规则（风控优先）**
- R1：启动前必须通过风控校验（详见第 9 章）。
- R2：启动必须二次确认：密码 + 2FA（若开启）。
- R3：运行中实时监控：
  - 当日亏损达到阈值 → 自动平仓 + 停止策略
  - 最大回撤达到阈值 → 自动止停
  - 账号连接异常 → 重试并告警，超过时间自动停止
- R4：实盘所有信号与下单动作均写入审计日志。
- R5：支持手动暂停 / 终止；终止时可选择"仅停止下单"或"停止并平所有仓"。
- R6：V1 首版建议默认实盘需人工复核（半自动模式），即信号推送后用户点"确认下单"才执行；全自动可作为开关。

## 8. AI 能力需求

### 8.1 模型适配能力

- **多模型支持**：系统需可配置接入 OpenAI、Anthropic Claude、本地 Ollama 三类后端，通过统一抽象接口切换。
- **流式输出**：对话场景默认开启 SSE 流式；报告生成场景可选异步后通知。
- **Token 统计**：按会话统计输入/输出 Token，记录在用户账上（便于后续计费）。

### 8.2 RAG 检索能力

- **分块策略**：文本按章节语义边界分块，块大小默认 500~1000 字符，10% 重叠。
- **向量模型**：支持 text-embedding-ada-002、bge-large 等可配置。
- **召回 + 重排**：向量 Top-N 召回 + 可选重排（Reranker）。
- **引用溯源**：回答末尾列出来源书名、章节，可跳转。

### 8.3 AI 能力矩阵

| AI 功能 | 输入 | 输出 | 失败兜底 |
|---------|------|------|----------|
| 书籍解析 | PDF/EPUB 文件 | 目录、章节、文本 | 解析失败通知 + 支持手动粘贴 |
| 交易系统提取 | 书籍分块 | 结构化策略规则（4 部分） | 用户手动填写模板 |
| 市场分析报告 | 币种 + 周期 + K 线/指标 JSON | 6 部分文本报告 | 返回"当前 AI 不可用，展示原始指标数据" |
| 交易信号 | 行情 + 策略条件 | 信号卡片 | 规则引擎降级仅生成规则信号 |
| 风险诊断 | 持仓 + 波动率 | 风险等级 + 建议 | 展示基础风控数据 |
| 报告生成 | 交易数据 + 指标 | 日报/周报/月报文本 | 生成纯数字版本（无自然语言） |
| 策略优化建议 | 交易历史 + 策略参数 | 优化方向文本 | 列出指标问题点清单 |

### 8.4 Prompt 管理

- 模板分类存储：市场分析、信号生成、风险、报告、策略优化、书籍问答、通用对话。
- 支持变量插值：{{symbol}}、{{timeframe}}、{{user_trades}} 等。
- 支持版本化，便于 A/B 测试与回滚。
- 关键模板内置 few-shot 示例提升效果。

## 9. 风控与合规要求

### 9.1 资金安全

| 要求 | 措施 |
|------|------|
| API Key 保护 | AES-256 加密存储，密钥分离管理；日志中脱敏；解密仅限内存使用 |
| 权限最小化 | 默认只开通"只读 + 交易"，提币权限默认禁止，V1 首版建议锁死提币 |
| 连接隔离 | 只读账号用于监控，交易账号独立存储 |
| 多签防护 | 实盘启动需密码 + 2FA（可选）双因素 |

### 9.2 交易风控

| 类型 | 阈值（默认值，可配置） |
|------|------------------------|
| 单笔最大亏损 | 总资金的 2% |
| 单日最大亏损 | 总资金的 5% |
| 最大连续亏损次数 | 5 次 |
| 策略最大回撤 | 20% |
| 最大同时持仓数量（同币种） | 2 |
| 最大总持仓数 | 10 |
| 单日最大下单次数 | 100（防死循环） |
| 单次下单 USDT 上限 | 50,000 |

- 实盘运行中任一阈值触发 → 自动执行止停策略并告警。

### 9.3 系统安全

- 传输 HTTPS 强制开启。
- CORS 白名单配置。
- 接口限流：登录 10 次/分钟；交易下单 30 次/分钟。
- 文件上传白名单：仅 PDF/EPUB/TXT/DOCX。
- 所有敏感操作（新增账号、删除交易、实盘相关）写入审计日志。

### 9.4 合规与免责

- 系统首屏/登录页显著展示**风险免责声明**：
  > 本平台仅提供交易管理、分析与辅助工具，AI 生成内容及交易信号仅供学习研究参考，不构成任何投资建议。加密货币交易具有极高风险，您应根据自身情况独立决策并承担全部损失。
- 用户首次登录必须勾选"我已阅读并同意风险提示"后才能继续使用。
- 策略回测结果展示显著提示："历史表现不代表未来收益。"
- V1 首版不接入法币入金出金功能。
- 遵守所在地区法律法规：不向受限制地区提供服务（可后续配置 IP 白/黑名单）。

## 10. 非功能需求

### 10.1 性能

| 场景 | 指标 |
|------|------|
| 普通 API（登录/列表/详情） | 平均响应 ≤ 300ms，P95 ≤ 800ms |
| 图表统计接口（大范围） | 响应 ≤ 2s（可缓存 30s） |
| 回测任务 | 1 年 1h 级别数据 ≤ 1 分钟（可异步） |
| 行情推送延迟 | 从交易所到前端 ≤ 1s |
| 并发 | 同时在线 200 用户，实盘策略 50 个不阻塞 |
| AI 首字响应（流式） | ≤ 5s |

### 10.2 可用性

- 系统整体可用性 ≥ 99.5%（每月 downtime ≤ 3.6 小时）。
- 核心链路（登录、交易查询、行情展示）具备重试与降级。
- 数据库每日全量备份 + 实时 WAL 归档。

### 10.3 可扩展性

- 交易所接入采用插件化，新增交易所不改核心代码。
- AI 模型适配采用适配器模式，便于新增本地模型。
- 策略引擎与执行层解耦，支持多策略并发运行。

### 10.4 兼容性

- 前端支持 Chrome / Edge / Safari / Firefox 最新 2 个版本。
- 自适应支持：PC 端 1366×768 以上（V1 主做 PC，Pad 兼容，手机可用但不优先）。
- 后端 Python 3.11+；Node LTS 用于前端构建。

### 10.5 国际化与多语言

- V1 首版仅支持简体中文。
- 前端 i18n 框架预留，后续可扩展英文等。
