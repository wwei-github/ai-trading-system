## 1. 需求背景与目标

### 1.1 背景

当前系统已实现基于规则引擎的向量化回测（[backtest_engine.py](file:///Users/wangwei/Documents/个人项目/ai-trading-system/backend/app/utils/backtest_engine.py)），采用"一次性拉取全量 K 线 → numpy 向量化计算"的方式快速产出结果。这种方式虽然性能优秀，但存在以下局限：

| 局限 | 说明 |
|------|------|
| 无法模拟真实交易节奏 | 真实交易中，交易者逐根 K 线观察、分析、决策，而非一次性看到全部数据 |
| 不支持 AI 辅助决策 | 向量化计算无法在逐根 K 线时调用 AI 分析，无法模拟"AI 辅助人工决策"的场景 |
| 回测终止条件单一 | 仅支持"开始日期~结束日期"的区间模式，无法指定"从某时间点开始测试 N 根 K 线"的灵活模式 |
| 交易记录维度不足 | 未记录 AI 分析理由、止盈止损价、交易计划等内容，复盘时缺少决策依据 |

### 1.2 目标

设计一套**全新的 AI 驱动回测模式**，与现有向量化回测并存，支持：

1. **逐根推演**：模拟真实交易场景，逐根 K 线推进，每根 K 线触发 AI 分析。
2. **AI 辅助决策**：在每根 K 线获取更新行情后，AI 结合策略与当前市场状态，制定交易计划。
3. **灵活回测范围**：支持"从指定时间开始，测试 N 根 K 线"或"测试 N 天/小时"两种模式。
4. **完整记录**：每笔交易的决策过程（AI 分析、止盈止损、理由）、盈亏结果、总结统计均可查看。
5. **配置不可变**：回测开始后所有配置参数锁定，直到结束。

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| 真实模拟 | 模拟真实交易节奏，逐根 K 线推进，每次只看到当前及历史数据 |
| AI 驱动 | 每根 K 线调用 AI 进行市场分析，而非仅依赖固定规则 |
| 完整可追溯 | 每笔交易的决策过程、AI 分析、止盈止损理由均可追溯 |
| 灵活可配置 | 支持多种回测范围定义方式，适应不同验证需求 |
| 双模式并存 | 不替代现有向量化回测，而是作为补充模式运行 |

### 2.2 现有系统局限详细分析

**局限一：向量化无法逐根调用 AI**

现有引擎采用 `numpy` 向量化计算，本质是"一次性输入全部数据 → 一次性输出全部信号"。而 AI 回测需要逐根推进：

```
向量化模式：    [K1 K2 K3 K4 K5 ... K100] → 一次性 → [信号 S1 S2 S3 ... S100]
AI 逐根模式：   K1 → AI 分析 → 决策 → K2 → AI 分析 → 决策 → ... → K100
```

**局限二：K 线数据范围定义不同**

现有回测使用 `start_date` + `end_date` 两个日期定义范围。新的 AI 回测需要支持：

- 指定开始时间，然后选择"测试 N 根 K 线"或"测试 N 天/小时"
- 在开始时间之前，需要先获取 N 根历史 K 线作为预热数据（用于计算指标）

**局限三：交易记录缺少 AI 属性**

现有 `BacktestTrade` 模型缺少以下字段：
- `ai_analysis`：AI 分析原文
- `trade_plan`：AI 制定的交易计划
- `stop_loss`：止损价
- `take_profit`：止盈价
- `open_reason`：开仓理由
- `close_reason`：平仓理由（现有只有 exit_reason 枚举）
- `ai_confidence`：AI 决策置信度

### 2.3 本方案与现有回测的关系

| 维度 | 现有向量化回测 | 新 AI 回测 |
|------|---------------|------------|
| 数据处理 | 一次性全量 | 逐根推进 |
| 决策方式 | 规则引擎 | AI + 规则 |
| 应用场景 | 规则验证、参数调优 | 策略模拟、AI 辅助决策验证 |
| 性能 | 快（<10s/年） | 慢（依赖 AI 调用速度） |
| 交易记录 | 基础盈亏 | 含 AI 分析、交易计划、止盈止损 |
| 配置锁定 | 否 | 是 |
| 两者关系 | 保持不动 | 作为新模式新增 |

## 4. 回测模式总体设计

### 4.1 回测流程总览

```
┌─────────────────────────────────────────────────────────────────────┐
│                        回测配置阶段                                  │
│  用户选择：策略、交易对、周期、初始资金、手续费、开始时间、回测范围    │
└──────────────────────┬──────────────────────────────────────────────┘
                       ↓
           ┌───────────┴───────────┐
           │    配置锁定，不可更改    │
           └───────────┬───────────┘
                       ↓
           ┌───────────┴───────────┐
           │  获取预热数据(300根K线)  │  ← 开始时间前 300 根
           └───────────┬───────────┘
                       ↓
           ┌───────────┴───────────┐
           │   逐根推进回测主循环    │  ← 核心循环
           └───────────┬───────────┘
                       ↓
           ┌───────────┴───────────┐
           │  达到终止条件 → 停止    │
           └───────────┬───────────┘
                       ↓
           ┌───────────┴───────────┐
           │  生成回测总结报告       │
           └───────────┬───────────┘
                       ↓
           ┌───────────┴───────────┐
           │  保存并展示结果         │  ← 单笔记录 + 总结
           └────────────────────────┘
```

### 4.2 逐根推进核心循环

```
对每根新 K 线（从开始时间第 1 根到最后一根）：
  ┌──────────────────────────────────────────────┐
  │ 1. 获取新 K 线数据（来自已拉取的数据集）        │
  │ 2. 构建当前市场状态（含此前所有 K 线 + 预热数据）│
  │ 3. AI 分析当前市场：                           │
  │    - 趋势判断、支撑阻力、技术指标               │
  │    - 检视当前持仓状态                          │
  │ 4. AI 制定交易计划：                           │
  │    ├─ 若无持仓 → 是否开仓 + 理由 + 止盈止损     │
  │    └─ 若有持仓 → 是否平仓 + 理由（含止盈止损触达）│
  │ 5. 执行决策：                                  │
  │    ├─ 开仓：记录开仓信息、AI 分析、计划          │
  │    ├─ 平仓：记录平仓信息、盈亏、AI 分析          │
  │    └─ 无操作：记录空操作                        │
  │ 6. 更新进度                                     │
  └──────────────────────────────────────────────┘
```

### 4.3 回测范围定义

用户选择"开始时间"后，可通过两种模式定义回测范围：

**模式 A：按 K 线数量**
```
用户指定：开始时间 + 测试 N 根 K 线
示例：2026-01-01 00:00 + 500 根 15m K 线
→ 实际测试范围：2026-01-01 00:00 至 2026-01-05 05:00（500 根 15m）
→ 预热数据：2025-12-30 前面的 300 根 15m K 线
```

**模式 B：按时间跨度**
```
用户指定：开始时间 + 测试 N 天/小时
示例：2026-01-01 00:00 + 3 天（时间单位最小为当前周期）
→ 实际测试范围：2026-01-01 00:00 至 2026-01-04 00:00
→ 预热数据：2025-12-29 前面的 300 根 15m K 线
```

### 4.4 回测周期支持

| 周期 | 代码 | 单根时长 | 预热数据覆盖 | 说明 |
|------|------|----------|-------------|------|
| 15分钟 | 15m | 15min | 75小时（3.1天） | 最小周期 |
| 1小时 | 1h | 1h | 300小时（12.5天） | |
| 4小时 | 4h | 4h | 1200小时（50天） | |
| 1天 | 1d | 1d | 300天 | 最大周期 |

## 5. 功能需求详细说明

### 5.1 F1 回测配置

#### 5.1.1 配置参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| 关联策略 | UUID | 是 | - | 从已有策略中选择 |
| 交易对 | string | 是 | BTC/USDT | 如 BTC/USDT、ETH/USDT |
| 周期 | enum | 是 | 15m | 15m / 1h / 4h / 1d |
| 初始资金 | float | 是 | 10000.0 | USDT，> 0 |
| 手续费率 | float | 是 | 0.001 | 单边费率，0.1% |
| 开始时间 | datetime | 是 | - | 精确到分钟，不低于当前时间前 30 天 |
| 回测模式 | enum | 是 | kline_count | kline_count（按K线数量）/ time_span（按时间跨度） |
| K 线数量 | int | 模式A | 100 | 1~5000 |
| 时间跨度值 | int | 模式B | 7 | 数值 |
| 时间跨度单位 | enum | 模式B | day | hour / day |
| 使用 AI | bool | 否 | true | 是否启用 AI 分析（false 则仅用规则引擎，保留 AI 记录格式） |

**业务规则**
- R1：开始时间必须 ≥ 当前时间 - 30 天（防止选择太早的历史数据增加预热数据获取难度）。
- R2：开始时间必须 ≥ 预热数据可获取的最早时间（即至少需要 300 根 K 线数据量）。
- R3：模式 A 的 K 线数量上限与周期相关：15m 最多 5000 根，1d 最多 500 根。
- R4：模式 B 的时间跨度最大为：15m 周期最多 30 天，1d 周期最多 365 天。
- R5：手续费率范围为 0~0.01（0%~1%），精度 0.0001。
- R6：初始资金范围为 100~100,000,000 USDT。

#### 5.1.2 配置验证

| 验证项 | 规则 |
|--------|------|
| 策略有效性 | 策略必须存在且非草稿状态 |
| 交易对有效性 | 通过 CCXT 验证交易对在交易所存在 |
| 数据可用性 | 验证交易所可获取到开始时间前 300 根 K 线 |
| 参数合理性 | 检查各参数范围合规 |

### 5.2 F2 预热数据

| 项目 | 内容 |
|------|------|
| 功能描述 | 在开始时间之前获取 300 根 K 线作为预热数据，用于计算技术指标 |

**业务规则**
- R1：预热数据数量固定为 300 根，与周期无关。
- R2：预热数据的时间范围为：从（开始时间 - 300 根 K 线的时间跨度）到开始时间。
- R3：预热数据通过 [coin_service.py](file:///Users/wangwei/Documents/个人项目/ai-trading-system/backend/app/services/coin_service.py) 的 `get_kline_data()` 获取。
- R4：预热数据同样受 CCXT 限流控制，需在回测开始前一次性拉取完毕。
- R5：预热数据仅用于计算指标（如 MA、RSI 等），不参与回测交易决策（AI 可参考）。

### 5.3 F3 逐根推进

| 项目 | 内容 |
|------|------|
| 功能描述 | 从开始时间开始，逐根 K 线推进，模拟真实交易节奏 |

**推进策略**

| 周期 | 推进间隔 | 说明 |
|------|----------|------|
| 15m | 每 15 分钟推一根 | 实际执行中为快速模式，不等待实际时间 |
| 1h | 每 1 小时推一根 | |
| 4h | 每 4 小时推一根 | |
| 1d | 每 1 天推一根 | |

**业务规则**
- R1：推进是**逻辑上的逐根**，不等待实际时间流逝。用 `for` 循环迭代已预拉取的数据集。
- R2：每根 K 线推进时，AI 只看到"当前及之前的所有 K 线 + 预热数据"，看不到未来数据。
- R3：推进速度由 AI 调用延迟决定，不做人为延迟。
- R4：每根 K 线推进后记录推进状态，支持断点续跑（V1.1）。

### 5.4 F6 配置锁定

| 项目 | 内容 |
|------|------|
| 功能描述 | 回测开始后，所有配置参数不可更改 |

**业务规则**
- R1：回测创建并提交后，立即进入"锁定"状态，配置参数不可修改。
- R2：回测状态包括：`pending`（待开始）→ `running`（运行中）→ `completed`（完成）/ `failed`（失败）。
- R3：`pending` 状态仅在提交后极短时间存在，可取消（删除回测记录）。
- R4：`running` 状态不可取消。
- R5：`completed` / `failed` 为终态，不可重复运行。
- R6：锁定参数包括：策略、交易对、周期、初始资金、手续费、开始时间、回测范围。

### 5.5 F7 单笔交易记录

| 项目 | 内容 |
|------|------|
| 功能描述 | 记录每笔交易的完整决策过程与结果 |

**每笔交易记录字段**

| 字段 | 类型 | 说明 |
|------|------|------|
| 交易编号 | 自增 ID | 按开仓顺序 |
| 方向 | enum | long / short |
| 开仓时间 | datetime | 开仓的 K 线时间戳 |
| 开仓价 | float | 开仓价格（K 线收盘价或指定价） |
| 开仓数量 | float | 建仓数量 |
| 开仓时 AI 分析 | text | 开仓时 AI 输出的市场分析原文 |
| 开仓理由 | text | AI 给出的开仓理由 |
| 开仓置信度 | int | AI 决策置信度 1~5 |
| 止损价 | float | 止损价格 |
| 止盈价 | float | 止盈价格 |
| 平仓时间 | datetime | 平仓的 K 线时间戳 |
| 平仓价 | float | 平仓价格 |
| 平仓理由 | text | 平仓原因描述（AI 决策 / 到达止盈 / 到达止损 / 时间止损等） |
| 平仓时 AI 分析 | text | 平仓时 AI 输出的分析（可选） |
| 持仓周期数 | int | 持仓跨越的 K 线根数 |
| 盈亏金额 | float | 平仓后计算 |
| 盈亏比例 | float | 百分比 |
| 手续费 | float | 该笔交易手续费 |
| 额外数据 | JSON | 扩展字段 |

**业务规则**
- R1：每笔交易记录一旦生成（开仓），不可修改。
- R2：平仓后自动计算盈亏并更新记录。
- R3：AI 分析原文保留完整，便于复盘查看 AI 决策过程。
- R4：止盈止损价在开仓时由 AI 设定，可在后续持仓期间由 AI 调整（更新记录）。

## 6. AI 分析与决策流程

### 6.1 AI 调用时机

| 时机 | 触发条件 | 说明 |

| 每根新 K 线 | 每推进一根 K 线 | 进行一次市场分析 |

### 6.5 AI 失败兜底

| 场景 | 兜底策略 |
|------|----------|
| AI 调用超时 | 等待 30s 后重试 1 次，仍失败则跳过该根 K 线（不操作） |
| AI 返回格式异常 | 解析失败，跳过该根 K 线（不操作） |
| AI 连续 3 次失败 | 暂停 AI 调用，转为纯规则引擎模式，记录"AI 已降级" |
| AI 返回不合理决策（如投入资金超限） | 校验后拒绝，记录"AI 决策被风控拦截" |
| AI 服务不可用 | 回退到规则引擎模式，不影响回测流程 |

### 6.6 AI 调用优化

- **缓存**：相同市场状态下的 AI 分析结果可缓存（V1.1）。
- **批量**：可考虑将多根 K 线的分析打包一次调用（V1.1，降低 Token 消耗）。
- **Token 控制**：控制输入长度，仅传入最近 50 根 K 线 + 持仓状态，不传全部历史。
- **流式**：AI 输出流式展示到前端，提升用户体验。

- 当前持仓状态（若有持仓，显示持仓方向、盈亏）。

#### 9.3.4 交易明细列表
- 支持按方向、盈亏状态、开仓时间筛选。
- 点击行展开详情，显示 AI 分析原文、开仓理由、止盈止损价。

#### 9.3.5 回测历史

## 10. 异常与边界处理

### 10.1 异常场景

| 场景 | 处理方式 |
|------|----------|
| 预热数据不足 300 根 | 提示"所选时间的数据不足，请调整开始时间"，不允许开始 |
| AI 调用超时/失败 | 跳过当前 K 线，记录日志，连续 3 次失败降级为规则引擎 |
| 回测过程中网络中断 | 回测任务在服务器端继续运行，用户可刷新页面查看进度 |
| 回测结果为空（无交易） | 正常显示总结，交易笔数为 0，提示"该策略在测试范围内未产生交易" |
| 参数校验失败 | 表单级错误提示，明确标出不合规字段 |
| 开始时间太老导致数据获取失败 | 提示"无法获取该时间的历史数据，请调整开始时间" |
| 策略规则为空 | 提示"策略规则为空，请先编辑策略规则" |
| 同时有多个 AI 回测运行 | 允许并行，但限制同一用户最多同时运行 3 个 |
| 回测中途手动停止 | 强制停止，已完成的交易记录保留，总结按已完成部分计算 |

### 10.2 边界情况

| 情况 | 处理 |
|------|------|
| K 线数量为 1 | 最小 1 根，但实际有意义的最小值建议 ≥ 10 |
| 初始资金极小（如 100 USDT） | 正常计算，但仓位管理可能导致开仓数量为 0 |
| 手续费率为 0 | 允许，用于理论测试 |
| 开始时间精确到秒 | 取整到当前周期的开始时间（如 15m 周期，对齐到 0/15/30/45 分） |
| 回测时间过长（如 5000 根 15m K 线） | 预估时间并提示用户，异步执行 |
| AI 返回的止盈止损价不合理（如止损 > 开仓价） | 校验后自动修正，记录"AI 参数已修正" |

## 11. 验收标准

### 11.1 功能验收

| 编号 | 验收项 | 通过标准 |
|------|--------|----------|
| AC1 | 创建 AI 回测配置 | 所有参数可正常配置，表单校验正确 |
| AC2 | 回测开始后配置锁定 | 无法修改任何配置参数 |
| AC3 | 预热数据获取 | 回测开始前自动获取 300 根历史 K 线 |
| AC4 | 逐根推进 | 每根 K 线依次处理，不跳过不重复 |
| AC5 | AI 分析调用 | 每根 K 线调用 AI 并记录分析结果 |
| AC6 | AI 开仓决策 | AI 分析后正确生成开仓/平仓/无操作决策 |
| AC7 | 止盈止损记录 | 每笔开仓记录止盈止损价 |
| AC8 | 平仓记录 | 平仓时记录盈亏、理由、AI 分析 |
| AC9 | 配置锁定 | 运行中所有配置不可修改 |
| AC10 | 进度展示 | 实时显示推进进度 |
| AC11 | 回测总结 | 展示完整指标卡片与图表 |
| AC12 | 交易明细可查看 | 点击展开显示 AI 分析原文 |
| AC13 | 历史记录 | 可查看历史 AI 回测记录 |
| AC14 | AI 降级 | AI 连续失败后自动降级为规则引擎 |
| AC15 | 回测结果导出 | 支持导出报告 |

### 11.2 数据验收

- 每笔交易记录的 AI 分析原文完整可读。
- 回测总结指标手工核算误差 ≤ 1%。
- 预热数据 + 回测数据的总 K 线数量与预期一致。
- 配置锁定后，数据库记录无变更。

## 12. 后续迭代规划

### V1.1 优化项
- 断点续跑：回测中断后可从上次位置恢复。
- AI 缓存：相同市场状态的 AI 分析结果缓存，减少 Token 消耗和延迟。
- 批量 AI 分析：将多根 K 线的分析请求合并为一次调用（降低延迟）。
- 多策略对比：同时运行多个策略的 AI 回测，对比结果。
- 参数网格搜索：AI 回测中自动测试不同参数组合。

### V1.2 功能扩展
- 实时 WebSocket 行情回放（模拟真实时间流速）。
- 多币种同时回测。
- AI 回测与实盘策略的联动（回测通过的策略直接启动模拟/实盘）。
- 回测报告 PDF 导出（含图表）。

### V1.3 高级能力
- AI 策略优化建议（基于回测结果的 AI 分析）。
- 回测结果对比（多个 AI 回测之间）。
- 自定义 AI Prompt 模板。
- 手动干预回测过程（在推进过程中模拟"人工干预"）。

## 附录 C：与现有向量化回测的对比总结

| 对比维度 | 现有向量化回测 | 新 AI 回测 |
|----------|---------------|------------|
| 数据处理方式 | 一次性全量向量化计算 | 逐根 K 线推进 |
| 决策方式 | 规则引擎（固定指标条件） | AI 大模型分析 + 规则参考 |
| 回测时间 | 快（1 年 1h 数据 < 10s） | 慢（依赖 AI 调用，500 根约 5-10 分钟） |
| 适用场景 | 参数调优、规则验证、快速筛选 | 策略模拟、AI 辅助决策验证、复盘学习 |
| 交易记录深度 | 盈亏、平仓原因（枚举） | AI 分析原文、交易计划、止盈止损、置信度 |
| 回测范围定义 | 开始日期 + 结束日期 | 开始时间 + K线数量 或 时间跨度 |
| 配置锁定 | 否 | 是 |
| 数据模型 | backtests + backtest_trades | ai_backtests + ai_backtest_trades + ai_backtest_kline_logs |
| 前置数据 | 区间内全部 K 线 | 预热 300 根 + 区间内逐根 |
