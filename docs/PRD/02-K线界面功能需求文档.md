## 1. 需求背景与目标

### 1.1 背景

币种分析模块需要一个可视化的 K 线图表，帮助用户观察币种价格走势。当前 [coins 页面](file:///Users/wangwei/Documents/个人项目/ai-trading-system/frontend/src/pages/coins/index.tsx) 仅为占位内容，需实现首个可用的 K 线展示界面。

### 1.2 目标

- 提供基础的 K 线图表展示能力，支持多周期切换。
- **MVP 阶段聚焦稳定可用**：不做实时行情推送，采用「按周期定时拉取」的方式更新最新 K 线，降低复杂度与服务器压力。
- 币种先固定为 BTC，为后续「添加币种界面」预留接口与状态位。

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| 简洁优先 | MVP 仅展示 K 线主图 + 成交量，不叠加复杂指标 |
| 稳定优先 | 采用定时拉取而非 WebSocket，避免长连接维护成本 |
| 可扩展 | 币种、周期均参数化，便于后续扩展 |
| 低成本 | 使用公开市场数据，无需用户绑定交易所 API Key |

## 3. 数据来源说明

### 3.1 数据来源结论

> **K 线数据通过后端服务调用 CCXT 库，从 Binance 公开 API 获取（无需 API Key）。**

### 3.2 数据链路

```
前端 React 组件
    │  HTTP GET /api/v1/coins/{symbol}/kline
    ▼
后端 FastAPI  路由层：app/api/v1/coins.py
    │  调用 CoinService.get_kline_data()
    ▼
后端服务层：app/services/coin_service.py
    │  通过 CCXTClient 调用
    ▼
交易所封装层：app/exchange/ccxt_client.py
    │  fetch_ohlcv(symbol, timeframe, limit)
    ▼
CCXT 库（ccxt.async_support）
    │
    ▼
Binance 公开 REST API（无需鉴权）
    │  GET https://api.binance.com/api/v3/klines
    ▼
返回 OHLCV 数据
```

### 3.3 现有能力确认

后端已具备完整能力，**无需新增后端开发**，仅需前端对接：

| 能力 | 现有实现位置 | 状态 |
|------|--------------|------|
| K 线接口 | [coins.py](file:///Users/wangwei/Documents/个人项目/ai-trading-system/backend/app/api/v1/coins.py) `GET /coins/{symbol}/kline` | ✅ 已实现 |
| 数据获取 | [coin_service.py](file:///Users/wangwei/Documents/个人项目/ai-trading-system/backend/app/services/coin_service.py) `get_kline_data()` | ✅ 已实现 |
| CCXT 封装 | [ccxt_client.py](file:///Users/wangwei/Documents/个人项目/ai-trading-system/backend/app/exchange/ccxt_client.py) `fetch_ohlcv()` | ✅ 已实现 |
| 默认交易所 | Binance（公开市场数据） | ✅ 已配置 |

### 3.4 为什么选择 Binance 公开 API

| 选项 | 优势 | 劣势 | 结论 |
|------|------|------|------|
| Binance 公开 API（CCXT） | 免费、稳定、数据全、无需 Key | 国内访问需代理 | ✅ 采用 |
| OKX 公开 API | 国内可访问 | 历史数据深度略弱 | 备选 |
| 自建数据库存储 K 线 | 可控、可离线 | 需采集任务、占用存储 | 后续优化 |
| 第三方付费数据源 | 稳定、聚合多所 | 成本高 | 暂不考虑 |

> **注**：后续可在后端配置中切换默认交易所，前端无感知。

### 3.5 限频与降级

- Binance 公开接口限频：1200 次/分钟（权重计），K 线接口权重为 1-2，远超单用户需求。
- 后端 `CCXTClient` 已启用 `enableRateLimit: True`，CCXT 自动限频。
- 单次请求 K 线数量 ≤ 1000 根（Binance 上限）。

## 4. 功能需求详细说明

### 4.1 F1 K 线主图展示

| 项目 | 内容 |
|------|------|
| 功能描述 | 以蜡烛图形式展示 OHLCV 数据 |

**业务规则**
- R1：图表类型为蜡烛图（Candlestick）。
- R2：涨跌颜色默认**红涨绿跌**（中国习惯），后续可在系统设置中切换为绿涨红跌。
- R3：K 线包含开、高、低、收四个价格点。
- R4：X 轴为时间，Y 轴为价格；Y 轴根据可见 K 线范围自适应缩放。
- R5：鼠标悬停显示十字光标与该根 K 线的 OHLCV 详情浮窗。
- R6：支持鼠标滚轮缩放、拖拽平移。
- R7：默认显示最近 200 根 K 线，最右侧为最新一根。

### 4.2 F2 成交量副图

| 项目 | 内容 |
|------|------|
| 功能描述 | 主图下方展示成交量柱状图 |

**业务规则**
- R1：成交量柱与对应 K 线时间对齐。
- R2：柱体颜色跟随对应 K 线涨跌色（涨为红、跌为绿，与主图一致）。
- R3：副图高度约为主图的 20%~25%，可拖拽调整（V1.1）。
- R4：成交量单位为基础币（如 BTC），Y 轴显示数值。

### 4.3 F3 时间周期切换

| 项目 | 内容 |
|------|------|
| 功能描述 | 顶部提供周期切换按钮组 |

**支持的周期（V1）**

| 周期代码 | 显示文案 | 单根时长 | 含义 |
|----------|----------|----------|------|
| 15m | 15分 | 15 分钟 | 最小周期（MVP 起步周期） |
| 1h | 1小时 | 1 小时 | |
| 4h | 4小时 | 4 小时 | |
| 1d | 1天 | 1 天 | |

**业务规则**
- R1：默认选中 **15m** 周期。
- R2：切换周期时立即重新拉取数据，并重置定时器为新周期。
- R3：切换周期不影响币种（仍为 BTC）。
- R4：周期按钮以单选按钮组（Radio Group）形式展示，当前选中项高亮。
- R5：**最小维度为 15 分钟**，不提供 1m / 5m 等更小周期。

### 4.4 F4 定时刷新

| 项目 | 内容 |
|------|------|
| 功能描述 | 按当前周期定时拉取最新 K 线 |

**刷新策略（核心）**

| 当前周期 | 刷新间隔 | 说明 |
|----------|----------|------|
| 15m | 15 分钟 | 每 15 分钟拉取一次，更新最新 K 线 |
| 1h | 1 小时 | 每 1 小时刷新一次 |
| 4h | 4 小时 | 每 4 小时刷新一次 |
| 1d | 1 天 | 每天刷新一次 |

> **核心规则**：刷新间隔 = 当前 K 线周期。即"15 分钟 K 线就每 15 分钟更新一次最新 K 线"。

**业务规则**
- R1：K 线**不做实时变动**（不订阅 WebSocket），仅在定时器触发时整体拉取。
- R2：刷新时仅增量更新最新 K 线，避免整图重绘闪烁：
  - 若最新 K 线的时间戳与图表最后一根相同 → 更新该根的 OHLCV
  - 若不同（产生了新的一根）→ 追加新 K 线，并移除最旧的一根（保持 200 根）
- R3：刷新请求只拉取最近 5 根 K 线（`limit=5`），用于增量更新，减少传输。
- R4：切换周期时立即触发一次完整拉取（`limit=200`），并启动新的定时器。
- R5：页面不可见（浏览器 Tab 切换到后台）时暂停定时刷新，可见时恢复并立即拉取一次。
- R6：定时器使用 `setInterval`，在组件卸载、周期切换、币种切换时清除旧定时器。

**对齐策略**
- 定时刷新不要求严格对齐到 K 线周期边界（如 10:15:00），MVP 阶段以"启动后每 N 分钟一次"的简单轮询为准。
- V1.1 可优化为对齐到周期边界刷新（详见第 11 章）。

### 4.5 F5 币种展示

| 项目 | 内容 |
|------|------|
| 功能描述 | 固定展示 BTC/USDT K 线 |

**业务规则**
- R1：MVP 阶段币种在前端**写死为 `BTC/USDT`**，不提供切换 UI。
- R2：币种以变量形式存储于组件 state（如 `const [symbol, setSymbol] = useState('BTC/USDT')`），后续接入币种选择界面时直接修改该 state 即可。
- R3：页面顶部显示当前币种名称 "BTC/USDT"。

### 4.6 F6 K 线数量与加载

| 项目 | 内容 |
|------|------|
| 功能描述 | 默认展示 200 根 K 线，支持滚动加载更多 |

**业务规则**
- R1：首次加载请求 200 根 K 线（`limit=200`）。
- R2：用户向左滚动到图表最左侧时，触发加载更多历史 K 线（每次 100 根）。
- R3：加载更多时使用 `since` 参数（最早 K 线时间戳 - 1）向前拉取。
- R4：单图表最多加载 1000 根 K 线，超过后不再加载（避免性能问题）。
- R5：加载中显示 loading 占位，加载失败提示重试。

### 4.7 F7 基础信息条

| 项目 | 内容 |
|------|------|
| 功能描述 | 图表顶部显示币种与行情概况 |

**展示信息**
| 字段 | 来源 | 说明 |
|------|------|------|
| 币种 | 写死 | BTC/USDT |
| 最新价 | K 线最后一根收盘价 | |
| 24h 涨跌幅 | 调用 `/coins/{symbol}/ticker` | 百分比，红绿色 |
| 当前周期 | 组件 state | 如 "15分" |
| 最后更新时间 | 最近一次刷新时间 | 如 "10:32:45" |

**业务规则**
- R1：最新价随 K 线刷新同步更新。
- R2：24h 涨跌幅独立请求 `/coins/{symbol}/ticker` 接口，与 K 线刷新同步触发。
- R3：最后更新时间用于让用户确认数据是否新鲜。

## 5. 数据结构与接口

### 5.1 现有接口（无需新增）

#### 获取 K 线数据

```
GET /api/v1/coins/{symbol}/kline?timeframe=15m&limit=200
```

**路径参数**
| 参数 | 类型 | 说明 |
|------|------|------|
| symbol | string | 交易对，如 `BTC/USDT` |

**Query 参数**
| 参数 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| timeframe | string | 否 | 1d | 周期：15m/1h/4h/1d |
| limit | int | 否 | 100 | K 线数量，1~1000 |

**响应（已有实现）**
```json
{
  "code": 0,
  "message": "ok",
  "data": [
    {
      "timestamp": 1691923200000,
      "open": 29000.5,
      "high": 29150.2,
      "low": 28980.1,
      "close": 29100.8,
      "volume": 123.45
    }
  ]
}
```

**字段说明**
| 字段 | 类型 | 说明 |
|------|------|------|
| timestamp | int | 毫秒级时间戳（K 线开盘时间） |
| open | float | 开盘价 |
| high | float | 最高价 |
| low | float | 最低价 |
| close | float | 收盘价 |
| volume | float | 成交量（基础币） |

#### 获取实时行情（用于 24h 涨跌幅）

```
GET /api/v1/coins/{symbol}/ticker
```

**响应（已有实现）**
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "symbol": "BTC/USDT",
    "name": "BTC",
    "current_price": 29100.8,
    "price_change_24h": 2.35,
    "volume_24h": 123456789.0
  }
}
```

## 6. 前端交互与状态

### 6.1 组件结构

```
CoinsPage (页面容器)
├── CoinInfoBar        基础信息条（币种、最新价、涨跌幅、最后更新时间）
├── TimeframeSelector  周期切换按钮组
└── KlineChart         K 线图表组件
    ├── MainChart      主图（蜡烛图）
    └── VolumeChart    成交量副图
```

### 6.2 组件状态

| State | 类型 | 默认值 | 说明 |
|-------|------|--------|------|
| symbol | string | 'BTC/USDT' | 当前币种（写死） |
| timeframe | Timeframe | '15m' | 当前周期 |
| klineData | KlineItem[] | [] | K 线数据 |
| ticker | TickerInfo \| null | null | 行情信息 |
| loading | boolean | false | 加载状态 |
| refreshing | boolean | false | 定时刷新中（轻量 loading） |
| lastUpdate | number \| null | null | 最后更新时间戳 |
| error | string \| null | null | 错误信息 |

### 6.3 关键交互流程

#### 流程 1：首次加载
```
进入页面
  → 设置 symbol='BTC/USDT', timeframe='15m'
  → 并行请求：getKline(BTC/USDT, 15m, 200) + getTicker(BTC/USDT)
  → 渲染图表 + 信息条
  → 启动定时器 setInterval(15min)
```

#### 流程 2：切换周期
```
点击 "1h" 按钮
  → 清除旧定时器 clearInterval
  → 设置 timeframe='1h', loading=true
  → 请求 getKline(BTC/USDT, 1h, 200)
  → 更新 klineData，loading=false
  → 启动新定时器 setInterval(1h)
```

#### 流程 3：定时刷新
```
定时器触发
  → refreshing=true
  → 请求 getKline(BTC/USDT, 15m, 5)  // 仅拉最近5根
  → 与现有 klineData 末尾对比：
      - 时间戳相同 → 替换最后一根
      - 时间戳不同 → 追加新根，移除最旧根
  → 更新 lastUpdate
  → refreshing=false
```

#### 流程 4：加载更多历史
```
用户向左滚动到图表最左
  → 取 klineData[0].timestamp 作为 since
  → 请求 getKline(BTC/USDT, 15m, 100)（带 since 参数，需后端支持）
  → 注：现有接口未暴露 since 参数，需评估是否补充
  → 将新数据 prepend 到 klineData 前部
```

> **注**：F6「加载更多」依赖后端 `since` 参数。当前 [coins.py](file:///Users/wangwei/Documents/个人项目/ai-trading-system/backend/app/api/v1/coins.py) 接口未暴露 `since`，需在 V1.0 中补充或顺延到 V1.1。

## 7. 定时刷新策略

### 7.1 刷新间隔对照表

| 周期 | 刷新间隔 | 每日刷新次数 | 单次请求量 |
|------|----------|--------------|------------|
| 15m | 15 分钟 | 96 次 | 5 根 |
| 1h | 1 小时 | 24 次 | 5 根 |
| 4h | 4 小时 | 6 次 | 5 根 |
| 1d | 1 天 | 1 次 | 5 根 |

### 7.2 刷新时机说明

- **不要求对齐到周期边界**：例如用户在 10:07 进入 15m 周期，则下次刷新为 10:22，而非 10:15。
- **理由**：MVP 阶段简化实现，避免处理时区对齐与时钟漂移。V1.1 优化为对齐刷新。

### 7.3 刷新请求优化

- 定时刷新只请求最近 5 根 K 线（而非全部 200 根），降低带宽与服务器压力。
- 增量合并逻辑见 4.4 R2。

### 7.4 定时器生命周期

| 事件 | 定时器动作 |
|------|------------|
| 组件挂载 | 启动 |
| 组件卸载 | 清除 |
| 切换周期 | 清除 → 启动（新间隔） |
| 切换币种 | 清除 → 启动（相同间隔） |
| 页面切到后台 | 清除（暂停） |
| 页面切回前台 | 立即拉取 → 启动 |

## 8. 异常与边界处理

### 8.1 异常场景

| 场景 | 处理方式 |
|------|----------|
| 首次加载失败 | 图表区显示空状态 + "加载失败，点击重试" 按钮 |
| 定时刷新失败 | 静默失败，保留上次数据，3 次连续失败后提示"数据更新异常" |
| 网络断开 | 定时器继续运行，恢复后自动拉取 |
| K 线数据为空 | 显示"暂无数据" |
| 接口返回错误码 | 显示错误信息 + 重试按钮 |
| 交易所限频（429） | 后端已通过 CCXT 自动限频；若仍触发，前端退避重试 |

### 8.2 边界情况

| 情况 | 处理 |
|------|------|
| K 线数量不足 200 根 | 按实际数量展示 |
| 最新 K 线时间戳跳跃（交易所维护） | 正常展示，不做特殊处理 |
| 价格异常波动（如闪崩） | 正常展示，不做过滤 |
| 用户长时间停留页面 | 定时器持续运行，数据持续更新 |
